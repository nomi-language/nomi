# Nomi Implementation Status

A contributor dashboard. The spec, [`spec.md`](spec.md),
is canonical for what the language does: **if a feature appears there
without a "Status: not yet implemented" callout, it works.** This file does
not re-list language features. It tracks compiler and tooling milestones, a
punch list of spec sections that are still aspirational, and known defects.

For the forward view (big-ticket initiatives and their order) see
[`roadmap.md`](roadmap.md).

---

## Aspirational language features

Spec sections with a "Status: not yet implemented" callout.

- [§8 Variants as Parameter Types](spec.md) — a struct variant declared inline is not a type: `fn f(r: Rectangle)` and `fn f(r: Shape.Rectangle)` are both `unknown type`. Embedded structs work.
- [§16 Strings: Display for function values and Iters](spec.md) — `"${f}"` or `io.print(f)` on a function value or a lazy `Iter` passes the checker, and the program is refused before it runs with a "not supported yet" error rather than a type error.
- [§10 Pattern Matching: `or` between patterns](spec.md) — `when` guards work; `a or b` in a `case` arm is a parse error, and no alternative-pattern node exists.
- [§15 Type Aliases: generic aliases](spec.md) — `typealias Name Target` works; `typealias Name<T> ...` is a parse error at the `<`.
- [§31 CLI surface (`nomi add`, `nomi publish`)](spec.md) — `nomi run`, `nomi build`, `nomi test`, `nomi check` and `nomi fmt` ship; `add` and `publish` wait on the registry question below.
- [§31 Project config: dependencies without a local `replace`](spec.md) — a `require` with no local `replace` is skipped, so a dependency is not fetched through the Go module proxy yet.
- [§31 Registry & Distribution](spec.md) — no Nomi-specific registry. A Nomi module is a Go module, so distribution rides the Go module proxy.
- [§31 Compiler-Enforced Semver](spec.md) — long-horizon. Needs a registry to compare against and a published-API extraction step.

`grep -n "Status: not yet" docs/spec.md` should
match each item above.

## Decisions: intentionally not adopted

- **Interface composition / `extends`.** Multi-bound `where` clauses (`where T: A and B`) cover consumer-side composition, and `embeds` enums cover heterogeneous collections, so an interface-inheritance mechanism would add a second way to say both.
- **Read-only (matchable but not constructable) fields.** `opaque` stays all-or-nothing: a type either exposes its fields for construction, matching and access, or hides all three behind its own functions.

## Known quirks and open defects

- **`continue` in `Iter.loop` retries with the same state.** By design, and stated in the spec's `loop` section. `continue (i + 1, s)` is a checker error naming the working form (`internal/analysis/continue_value.go`).
- **Programs the checker accepts and the VM cannot run.** The IR builder declines some bodies. `nomi check` lowers the program without running it and reports each declined body that `main` or a test reaches as an error at the expression the builder stopped at (`vmhost.Program.Unsupported`), one per function; a function only a declined function calls is reported once its caller lowers. It takes test files and directories of them, and lowers each case as `nomi test` would; on a stdlib module it lowers the module's `//!` cases. `nomi run` stops with the same errors before its first effect, and `nomi test` reports each case it cannot run as `BLOCKED` with the same error; `NOMI_DEBUG_LOWERING=1` adds the builder's own reason to each as a hint. The language server reports them when a file is opened or saved and 400 ms after the last edit of a burst (`internal/lsp/lowering.go`). Known shapes:
  - `Debug.inspect` of a tuple, record or other structural value holding two instantiations of one generic type, as in `Debug.inspect((Box{v: 1}, Box{v: "a"}))`. The renderer finds a nested value's Debug body by runtime type name, which every instantiation shares, so the String one is handed to the Int one's body, and the VM stops with a machine limit. This one lowers, so `nomi check` does not report it. One instantiation, or a `List` of either, runs.
  - A payload-free variant of a user generic enum whose type argument nothing constrains, as in `(Box.Empty, 1)`. There is no instance to build it at.
  - A block whose value has a type declared inside that block, as in `w = { struct Loc { n: Int } Loc{n: 1} }`. The binding is typed at the block-local type, which the builder cannot resolve outside the block, so it declines with "its body is not supported yet". A block that uses the type only inside itself runs.
  - A variant of a user enum imported by name from another file (`import shapes.Shape.Circle`, then `Circle(1)`, or `Rect{w: 3}` for a struct-shaped one). The qualified `Shape.Circle(1)` runs, and so does a std enum's variant imported by name.
  - A function with a defaulted parameter named as a value at its full type, as in `g = parse` or `g: (String, Bool) -> Maybe<Int> = parse` for `fn parse(s: String, strict: Bool = False)`. The unannotated value keeps its defaults (`g("1")` fills `strict`), and the builder has no value representation that carries them (`internal/irbuild/funcref.go`). A lambda or a partial application (`parse(_)`) runs.
  - A binding `else` that supplies a fallback for an `embeds` variant whose payload pattern is anything but a bare name. The checker accepts it; the builder does not lower that payload pattern (`internal/irbuild/irelsebinding.go`). A bare name, or an `else` that leaves, runs.
  - A block statement, `{ ... }`, in an inline `Iter.loop` callback whose nested `if` leaves the iteration (`{ if c { return next } }` or `{ if c { break v } }` followed by more statements). The loop body admits only straight statements beside its guards (`loopBody` in `internal/irbuild/irloop.go`), so it declines with "an Iter.loop body statement that branches" or "a Break". The same `if` written directly in the callback is a guard and runs, and so does such a block in a function or lambda body.
  - A `break` or `continue` in the callback of an iteration function other than `Iter.map`, `filter`, `take_while`, `each`, `iterate`, `reduce` and `loop`, such as `Iter.find`, `any?`, `all?`, `drop_while`, `flat_map` or `Map.map_values`, whether the callback is a lambda or a named function that uses them. The checker admits these positions; the VM has no signalling form of those operations.
  - An `import` at the top of a block that rebinds a name the file already binds to something else, as in `import std/duration.Duration` inside a function of a file that declares its own `Duration`. The builder resolves some names by the file's scope rather than by position, so it declines with "an `import` in a block that rebinds a name the module scope binds differently" (`testImport` in `internal/irbuild/stdtests.go`). A block import of a std file, of a name the file does not bind, runs, including types named through its qualifier (`json.Json.Null`). The same qualifier imported by two blocks from different files declines.
  - A direct call to a named function that uses `break` or `continue`, including from inside a callback lambda (`Iter.map(xs, |x| skip_odd(x))`) or from another such function. Pass the function itself as the callback (`Iter.map(xs, skip_odd)`), which runs.
- **`derive ToJson` and `derive FromJson` in a file that declares its own `Json`.** The derived code names `Json` and `Json.ShapeError`. When the file's scope binds no such name, derived code reaches std's declaration (`synthStdDecls` in `internal/analysis/derive_synthesis.go`); when the file binds it, derived code uses that binding, so a file's own `Json` type makes the derive fail with "undefined type Json.Obj". Shadowing it in derived code only would need the IR builder's name-keyed type tables to resolve by position.
- **A line comment after a payload-free enum variant is a parse error.** `ToJson // note` inside an enum body reports "expected type name, got COMMENT"; a comment on its own line parses.
- **An impl for another file's type is not found when the implementing file declares a type of the same name.** With `impl Html for users.User` in a file that also declares its own `User`, `Html.to_html(users.User{...})` is rejected with "no impl of `Html` for `User`", and the message does not qualify the name.

## Compiler

- [x] Guaranteed tail calls: `analysis.MarkTailCalls` marks tail positions and the VM runs a tail call by replacing the caller's activation (spec §12).
- [x] Generic functions, types and impls are instantiated per type-argument tuple by the IR builder; existentials dispatch at run time (spec §13).
- [x] The IR builder's own type is `kind` (a tag plus declaration pointers); it holds no Go type text or Go names.
- [x] Interface dispatch selects the body by the declared `self` position's runtime type (`ir.NewDispatchCall`, `internal/vm/dispatch.go`).
- [x] Impl manifest and missing-impl diagnostic: the analyzer records every `(Iface, T)` pair a program demands, and `DetectMissingImpls` (`internal/analysis/missing_impl.go`) reports a pair no impl supplies.
- [x] Impl coherence: `detectImplCollisions` and the orphan rule `detectOrphanImpls` (`internal/analysis/impl_coherence.go`, spec §13).
- [x] Nominal identity is (declaring file, name) for structs, enums, distincts and interfaces, through the dispatch key.
- [x] Universal `Debug`: `SynthesizeUniversalDebug` gives every declared type a `Debug` impl; opaque types render `<opaque T>`, and a lazy `Iter` renders `<iter>` without consuming it (spec §16).
- [x] Strong `Comparable` demand: `<`/`>`/`<=`/`>=` on a type with no `Comparable` impl is a compile error.
- [x] Opacity is enforced at the operation, including `Struct.update`.
- [x] Member access is fail-loud: a member a resolved value does not have is a compile error.
- [x] `Iter` is a push protocol (`each_while`, plus the `known_count` default); every algorithm is an `Iter` owner function.
- [x] A declared `Iter<T>` is a value type: struct fields, tuple and record parts, `Some`/`Ok` and enum payloads, parameters, results, list elements and closure captures all hold one, and a collection, Range or user `Iter` implementor passed where an `Iter<T>` is declared keeps its known count and its Debug text.
- [x] `Struct.update` through the universal `Struct` interface.
- [x] Scoped application fields, `boot`, `Context` and `defer` (spec §27, §28): an entry file's `fn boot(): App` or `fn boot(startup: Startup): App` (the parameter may have a default) builds the application value, reads name the application type (`App.field`), the statement `with App.field = v` replaces a field to the end of its block, and each `main` and test is checked against its own boot.
- [x] A `fn main` that returns `Err(e)` fails the run (spec §26): `nomi run`, a `nomi build` executable and the tour print `error: ` and `e`'s Display text (its Debug text when its type has no Display) to stderr and exit 1. `vmhost.Program.Run` answers it as a `*vmhost.MainError`.
- [x] A `fn main` declared to return anything but `Unit` or `Result<Unit, E>` is a checker error at its return type (spec §26), so `nomi check`, `nomi run` and the LSP all report it. A `fn main` that declares parameters is a checker error over its parameter list.
- [x] A body whose return type is `Unit`, written or omitted, may end in a `dbg` observation (`dbg x`, or a pipe ending `|> dbg`): the checker types the body `Unit`, and the builder runs the observation as a statement and returns `Unit`, in top-level, impl and nested functions.
- [x] Structured diagnostics. An analyzer error (`analysis.TypeError`) carries the span it is about, its advice as separate hints and the declarations it refers to as related locations. The parser records every expression's, pattern's and type's extent (`ast.Span`), and an error reported at a point is widened to the token there (`analysis.CompleteSpans`). Converted to spans, hints and related locations: type, argument, element and return mismatches (a return mismatch spans the body's last expression and points at the declared return type), undefined names and unknown fields, types, variants and members (the "did you mean" is a hint), missing struct fields, non-exhaustive `case`, missing impl functions and impl parameter names (both point at the interface function), duplicate declarations (point at the first), missing impls (other demand sites are related locations), the self-render error, the `then`-stage boundary, `_` as a value, and unread bindings and parameters. An error inside a lambda body or a tuple element leaves the enclosing value's type unknown, so it draws no second mismatch.
- [x] `nomi check`, `nomi run`, `nomi build` and `nomi test` print each diagnostic with its source line and its span underlined, then `= help:` and `= note:` lines, coloured on a terminal (`NOMI_COLOR`, `NO_COLOR`). `nomi check --format short`, or `NOMI_DIAGNOSTICS=short` for any command, prints the `path:line:col: message` form instead, with each hint and related location as a `path:line:col: help: ...` or `note: ...` line; that form is also the `Error()` text `vmhost` returns and the message of a `nomi test --format json` file record. `vmhost.Diagnostic` carries the span, hints, related locations and the source line as data. The REPL prints hints under the error.
- [x] Tests: `test`/`tests` declarations, `//!` attached tests, `nomi test`, virtual clocks (spec §36). A group names an entry's boot on a `boot` line, and its `setup` value reaches each test through an irrefutable pattern.
- [x] `compiler.check`, `compiler.check_project`, `compiler.run` and `compiler.hover` for tests about the compiler.
- [x] Concurrency: `concurrent { }`, tasks, channels, `Supervisor`s with restart policies and drain (spec §20). Supervised failures are reported to stderr; there is no in-program failure channel.
- [x] `Decimal`, calendar types, random generation, `Dynamic` and `std/json` with derive (spec §39, §40).
- [x] Irrefutable parameter destructuring (spec §5).
- [x] Default parameter values, including on interface default functions; explicit generic headers and `where` clauses on functions, declarations, derives and impls.
- [x] A struct-shaped variant imported by name (`import std/supervisors.Backoff.Exponential`, then `Exponential{max_restarts: 3}`) types as its enum and checks its fields, in project and single-file analysis alike.

## Type Checker

Two phases: `BuildTypes` registers and resolves type definitions, `CheckTypes` walks bodies.

### Working

- [x] Function bodies: return types, argument types and counts, named arguments, defaults.
- [x] Operators, pipes, partial application (`_`), string interpolation.
- [x] Operator impls on a generic receiver (`impl Add<T, Box<T>> for Box<T>`), read at the left operand's type arguments, including in generic code.
- [x] Generic call-site unification, consistent type variables across parameters, generic propagation through higher-order functions.
- [x] Function type assignability (spec §5 *Type Annotations*): contravariant parameters and covariant results at every position a function value flows into (`UnifyInto` in `internal/analysis/unify.go`), with the builder's adapter closure doing the conversion (`internal/irbuild/irfuncwiden.go`); joins of two function types require the same type.
- [x] Generic functions used as values (`Iter.each(io.print)`, `Iter.map(xs, ident)`), instantiated against the expected function type with their bounds checked; an unannotated `f = ident` asks for an annotation.
- [x] Bidirectional lambda inference and lambda return unification, including a generic call's parameter that the call's expected type fixes (`f: (Int) -> Int = ident(|x| x + 1)`) and a generic struct's field or variant's payload that the expected type fixes (`f: Box<(Int) -> Int> = Box{v: |x| x + 1}`, `Some(|x| x)` against `Maybe<(Int) -> Int>`). A lambda parameter with no annotation or default where no function type is expected (an unannotated binding, a tuple or list element, a generic constructor's argument with no expected type such as `h = Some(|x| x)`) is `cannot infer type for parameter x`.
- [x] Binding inference, annotated bindings, destructuring bindings.
- [x] Struct, list, tuple, map and anonymous-struct literals, with map homogeneity.
- [x] ASCII codepoint literals (`'a'`, `'\n'`, `'\u{7F}'`), typed as std's `Codepoint` with no import (`analysis.TypeCodepoint`), as values, range ends and patterns at any depth; a malformed one is a lexer diagnostic (`strlit.DecodeCodepoint`), and a `case` over a `Codepoint` that tests literals needs a `_` arm.
- [x] Field accessors (`.name`, `.address.city`, `.0`, spec §8 *Field Accessors*): a function reading a field, typed from the expected one-parameter function type whose parameter is already known (`checkFieldAccessor`, `FileAnalysis.FieldAccessors`), and lowered to a closure over the same projections as `x.name` (`internal/irbuild/irfieldaccessor.go`). An accessor as a pipe stage, with no function expected, or before its parameter type is pinned is an error.
- [x] Target-typed struct literals: a brace literal with no type name builds the nominal struct its position expects (`a: Address = {street: …, city: …}`), lowered as `Address{…}` (`checkTargetTypedStructLit`, `FileAnalysis.TargetStructs`).
- [x] `if`/`case` branch consistency, pattern type checking, and `case` exhaustiveness over enums, tuples, structs, distinct types and lists (literal, prefix and map patterns need a catch-all) (`internal/analysis/exhaustive.go`).
- [x] `todo` (spec §5 *Unwritten Code*) has the type its position expects, including an `if` or `case` arm typed by its siblings and a generic result; an unannotated `x = todo` asks for an annotation, and a body holding a `todo` does not report unread parameters (`internal/analysis/todos.go`). It lowers to `ir.Todo`, a trap whose text is `rt.TodoError`'s.
- [x] `try`: operand must be `Result`/`Maybe`, and the propagated value must inhabit the boundary (spec §9).
- [x] Bindings with `else` (`Pattern = value else { ... }`, spec §10): every path of the else leaves or falls back to the pattern's one payload, else arms plus the pattern are exhaustive, a refutable pattern needs an `else` and an irrefutable one refuses it (`checkPatternBinding`).
- [x] `break`/`continue` context validation (`internal/analysis/iter_sensitive.go`).
- [x] A statement after `return`, `break` or `continue` in the same block is an unreachable-code error (`internal/analysis/unreachable.go`).
- [x] A Display `to_string` or Debug `inspect` that renders its own receiver (`"${foo}"`, `io.print(foo)`, `Display.to_string(foo)`, `dbg foo`, ...) is an error at the rendering (`internal/analysis/self_recursion.go`, spec §16).
- [x] A function every path of which calls itself with the arguments it was given is an error; a tail call counts only when nothing before it on its path calls anything (`internal/analysis/self_recursion.go`, spec §12 *Recursion depth*). Mutual recursion, calls inside lambdas and interface default bodies are not checked.
- [x] `embeds` subtyping, type aliases, generic enum inference, nested type-parameter identity.
- [x] Interface impl signature validation, field requirements, `open` defaults, `where` bounds.
- [x] Visibility consistency (§3) and naming conventions (§4).
- [x] Unused imports, redundant prelude imports, unused bindings and parameters are errors.
- [x] Cross-file calls are checked like same-file calls.
- [x] `==`/`!=` over an `Iter`, a function value, or a value holding one is a compile error naming the part (spec §30).
- [x] A `Set` element or `Map` key with no equality (an `Iter`, a function value, or a value holding one) is a compile error at the literal, call or pipe that builds the collection (`internal/analysis/equality_domain.go`).
- [x] A pipe stage is a call: a bare name (`x |> f`, `x |> io.print`, `x |> Ok`) is an error that names the call to write, and a `.Variant` stage asks for its enum (`internal/analysis/pipe_stage_call.go`, spec §6). The `then` stage (`x |> then |v| ...`) and the keyword stages are the stages that are not calls; a bare lambda stage is an error that names the `then` to write, with a quick fix that inserts it.
- [x] A type name is not a value and not a function: `f = Int`, `Iter.map(ids, Id)`, `x = calendar.Date`, `Int("4")`, `String(4)` and `Dir(1)` are errors at the name, with a hint naming the conversion where there is one (`internal/analysis/type_name_value.go`, spec §15 *Distinct Types*). A struct's record call form, a distinct's construction, the `Int`/`Float`/`String` unwrap of a distinct, variants, zero-sized types and `Type<T>` witnesses are unaffected.
- [x] A function value never fills a generic parameter whose shape is not a function, or the reverse: `Maybe.with_default(f, 0)` with `f: (String) -> Maybe<Int>` is an argument mismatch (`internal/analysis/func_value_shape.go`).
- [x] Only a function value can be called: `1()` or calling a tuple, list or struct value is an error at the callee (`` `Int` is not a function ``).
- [x] A generic argument whose outermost type differs from its parameter's is a mismatch even while the parameter's type variables are unsolved: `Set.size({})` (Unit), `List.head("x")` and `Maybe.some?(4)` are errors (`headDiffers` in `internal/analysis/func_value_shape.go`).
- [x] A file-qualified call to an inherent or impl function (`strings.trim(s)`) is an error whose hint names the owner form (`String.trim(...)`).
- [x] Two same-named types from different files are qualified in mismatch messages (`expected a.Point, got b.Point`).

### Not yet implemented

- [ ] Unused file-private declarations are not reported.
- [ ] A discarded call (`_ = f(x)`) is not diagnosed. Deciding that it is dead needs effect tracking, and purity is not enough: Nomi traps, so `_ = a + b` can fail on overflow and is observable.

## LSP

### Implemented

- [x] Diagnostics, document symbols, hover, signature help, semantic tokens, inlay hints. A diagnostic's range is the error's span (a parse error's is its token); its hints follow the message as `help:` lines, and its related locations are `relatedInformation` when the client declares `publishDiagnostics.relatedInformation`, `note:` lines of the message otherwise. The quick fixes (implement missing functions, add missing fields or arms, generate function, remove or add an import) match a diagnostic by its range, so a client that sends only the diagnostics under the cursor gets them anywhere in the span. A related location in a standard library file is left out: the analysis has no path for it. A document symbol's range is its declaration's extent (`ast.Span`, which the parser records: from the first token after any doc comment or `//!` test through the last), and its selection range is the name, for declarations, `test`s and `tests` groups and their members. A semantic token on a `//!` attached-test line carries the `attachedTest` modifier, which the Zed extension's `semantic_token_rules.json` uses to keep attached tests dimmed; Neovim and VS Code find attached tests themselves and leave the modifier unstyled.
- [x] Inlay hints (`internal/lsp/inlay_hints.go`, `pipe_hints.go`): parameter names, the types of unannotated bindings and lambda parameters, and the type a stage line of a multi-line pipeline produces (a pipeline with a `|>` that starts a line) where it differs from the line above's. A last stage whose type the binding's annotation, the binding-type hint or the enclosing function's declared return type already shows gets none. Each kind has a server setting, `inlayHints.parameterNames`, `inlayHints.bindingTypes` and `inlayHints.pipeTypes`, all on by default, read from `initializationOptions` or `workspace/didChangeConfiguration` (bare or under a `nomi` key); `workspace/configuration` is not requested. A request computes hints only for the pipelines on its lines, from the stored analysis, and lexes each analyzed text once. Pipe hints read the checker's recorded types, which leave some stages with their callee's type parameter unsolved (`List.range(0, n)` is recorded as `List<T>`; inside a lambda passed to `Iter.map`, an inner `Iter.reduce` stage as `U`); outside a generic function such a stage gets no hint.
- [x] Go-to-definition, find references and rename, same-file and cross-file.
- [x] Call hierarchy (`internal/lsp/call_hierarchy.go`): prepare on a function (module, impl or `host fn`, at its declaration or a use), then incoming and outgoing calls. A call is a call expression whose callee (`f`, `mod.f`, `Type.f`, a pipe stage) resolves to the function; a function passed as a value is not one. Callers are functions, impl functions, each `test` (a `tests` group's tests one by one) and `once` initializers, across the project: every open document and each closed file whose text holds the name, as references searches. A stdlib function has incoming calls but no outgoing ones, and an interface-qualified call (`Display.to_string(x)`) is not traced to the implementation it dispatches to.
- [x] Document links (`internal/lsp/document_link.go`): each import's path links to the file it names, the segments that name the file only (`std/maybe` of `std/maybe.Maybe.{None}`, `game` of `game.Game`). A stdlib module links to the materialized stdlib file go-to-definition opens; a project file, resolved as the analyzer resolves it (longest existing prefix, the module's own name stripped), links when it exists. A Go import, an import of another module's file and a path to a missing file get no link.
- [x] Code lenses (`internal/lsp/code_lens.go`): "Run test", "Run tests" and "Run attached test" above each `test`, `tests` group (and each test in it) and `//!` attached test, with the command `nomi.runTest` and arguments `[uri, line]`, the 1-based first line `nomi test <file> --line` selects it by; "Run" above a top-level `fn main`, with `nomi.runMain` and `[uri]`, for `nomi run <file>`. The client defines both commands: the VS Code extension runs them in its task terminal, and the Neovim plugin registers them in `vim.lsp.commands` for `vim.lsp.codelens.run()`. The Zed extension and the Helix config define no handler for them; Zed runs tests from `runnables.scm`.
- [x] Go to type definition (`internal/lsp/type_definition.go`): from a binding, parameter, field or `once` to its type's declaration; from a function or a call of one to its result type's; from a type name to itself. The declaration may be in this file, another project file, or the stdlib (a built-in such as `Int` or `List` included, in the materialized stdlib go-to-definition opens). A generic instantiation (`Maybe<User>`) lands on the generic type. A function type, a tuple, a type parameter and a file qualifier answer nothing.
- [x] Prepare rename (`internal/lsp/prepare_rename.go`): the name under the cursor and its text as the placeholder, or an error saying why it cannot be renamed. Rename refuses the same positions, and a new name that is not one identifier. Refused: a position with no symbol (keyword, literal, punctuation), a name declared outside the project (stdlib, prelude, another module), an import path segment or a path-only import's qualifier (rename the file instead), an implicit `it`, an interface method, and a function implementing one (rename edits one symbol, and the method and its implementations are separate symbols).
- [x] Document highlight (`internal/lsp/document_highlight.go`): the occurrences in the current file of the symbol under the cursor, matched as references are. A definition (binding, parameter, pattern name, declaration) is a Write, a use a Read; a shadowing binding is a separate symbol.
- [x] Application fields: hover, go-to-definition, references and rename on the field of `App.field` (the field's declaration) and on its type name (the type's), in reads and `with` targets.
- [x] A field label in an anonymous-struct literal is a reference to the annotated type's field, for hover, definition and references.
- [x] Completion (`internal/lsp/completion*.go`). The request reparses the file with a sentinel identifier at the cursor (`parser.ParseResilient`, so a half-typed body still completes) and reads the position from the tree; names, scopes and types come from the analyzed snapshot, possibly one edit old with positions mapped into it, and nothing is re-analyzed per request. In a statement the checker never saw, an expression's type is read from symbols, and a generic call's result is instantiated by unifying its parameter types with its arguments' types under the file's impl tables, the checker's own unifier (`first(points).` offers Point's fields, and `Iter.map(ns, to_point) |> Iter.to_list() |> ` offers what takes a `List<Point>`).
  - By position: declaration keywords at the top level, statement keywords at a statement start, operand keywords and names in an operand, only types in a type annotation, variants in a pattern, nothing in a string, a comment or a new name. A string's `${...}` (in a plain, triple-quoted or typed literal, closed or not) is an operand; a raw string's body is text.
  - A keyword that opens a block inserts its shape as a snippet, at the top level, a statement start or an operand (`completion_keywords.go`): `if ${1:condition} {…}`, `case ${1:value} {…}`, `fn ${1:name}(${2}): ${3:Unit} {…}`, `struct`, `enum`, `impl`, `test` (with `assert $0`) and `tests`, plus an `if else` item beside `if`. The shape replaces the bare keyword's item, so each keyword is listed once; without snippet support the item inserts the bare keyword and `if else` is not offered. A `//!` line, a string's `${...}` and a pipe stage keep the bare keyword.
  - A `//!` group is a test body: a name bound on an earlier line of the group is in scope with its type on its later lines (`u.` offers `u`'s fields), also while the line being typed does not parse, since the editor's resilient parse turns that line into an error node and keeps the group. A group's bindings reach neither another group nor the declaration.
  - `Owner.`: a type's inherent and interface-impl functions, an enum's variants, an application type's fields (only those after `with App.`); `Display.` an interface's functions and the owner functions declared on it (`Iter.map`); `T.` a type parameter's bounds' functions; `server.` a user or stdlib file's public members; `value.` the fields of the value's type and nothing else.
  - `import ` and `import std/` complete paths; `import x.{` the file's unselected public names.
  - A parameter name in a `fn` signature (module, impl, interface or host function, not a lambda) offers `name: Type` for each type in scope, named by the type's snake_case spelling (`game: Game`, `user_id: UserId`), so the list a client gets at the name's first letter already holds it; the type the whole typed name spells ranks first. After `name:` that type ranks first among the types. A generic type inserts a snippet with a tab stop per type argument (`List<${1}>`). The signature is read from the tokens, so an unclosed one (`fn slay(game, mon`) completes too. A type position offers only the modules the file imports as qualifiers, not the file's own module name or `prelude`.
  - Items carry the hover signature as detail and the doc comment on `completionItem/resolve`; calls insert as snippets with placeholders for required parameters only, falling back to plain text without client snippet support; every item replaces the whole word, in UTF-16 columns.
  - The expected type (the checker's recorded `ExpectedTypes`, or the slot's declared type while the statement does not parse) limits `.` to the expected enum's variants and ranks fitting items first, then locals, the file's names, imports, and names that need an import.
  - Where the expected type is a one-parameter function over a struct (`Iter.map(users, .‸)`, `users |> Iter.map(.address.‸)`, `get: (User) -> Int = .‸`), `.` offers the fields the field accessor can read, with a generic call's type parameters solved from its other arguments and the piped value (`FileAnalysis.CallArgParamType`). Hover and go-to-definition on an accessor's segment show and reach the field.
  - Where the expected type T is a nominal type (a struct, enum, distinct, opaque or host type, not a primitive, a List or an interface), an operand also offers the ways to build one (`completion_constructors.go`): T's inherent owner functions that return T and take no T, as owner-qualified calls (`Duration.seconds(${1:n})`, `Map.empty()` against `Map<String, Int>`); at `Maybe<X>` or `Result<X, E>`, X's functions returning exactly that (`Date.parse(s)` where `Result<Date, Error>` is expected, not where a plain `Date` is); and, when T implements `Literal`, a typed literal from its docs' first example (`Date"2026-05-04"`). They match on the function's name (`no` finds `Instant.now()`), rank with the fitting items after locals, and an owner the file does not name adds its import as auto-import does. A struct is not offered as a `T{...}` literal; its name is, and `{` then completes its fields.
  - Names from unimported stdlib and project files (a file object, a public type, `io.read_line`) add their import on accept, merged into an existing import; prelude names are never imported again.
  - A struct literal offers its unwritten fields, a patch (a spread, or a bare brace at a field under one) in declaration order since it needs none. A bare `{‸}` or `{ci‸}`, which reparses as a block, offers the fields of the nominal struct its position expects (a struct literal's field, an annotated binding, an argument, a return or block tail, a typed list item, a case arm, a patch's field) and nothing new elsewhere (a function's or an if's block, a map, an interface, no expected type). A word right after a field's value with no `,` (`{..p, address: {}‸}`) is not offered the literal's fields. A struct pattern offers the fields it does not name yet, as bare names (the punned `Point{x, y}`), in a case arm, a destructuring binding, an `assert` pattern, a parameter, a variant's payload or a tuple, with the type read from the pattern's head or its position (an unclosed one in a case arm too; an unclosed one at a statement start reads as a struct literal until its `}` and `=` are written); a case over an enum offers all its missing arms in one snippet; a `tests` group offers `clock`, `boot`, `setup`, `test` in grammar order and its entry boots after `boot`.
  - At a line start in an `impl Iface for T` body, or after `fn ` there, the interface's functions the block does not define, each inserting its whole declaration with an empty body: `self` spelled as the header spells `T`, a lone self parameter named by `T`'s snake_case spelling (`item: Item`, `box: Box<T>`), other parameters and defaults as the interface declares them (an impl must keep their names). An interface type argument comes from the header (`impl Add<Days, Date>`) or from a function the block already defines; an unknown one is a linked placeholder (`(${1:T}) -> Bool`). Required functions come first, then the `open` defaults, labelled `default:`; a final default is never offered. With two or more required functions missing, a first item writes them all. Read from the tokens, so an unclosed block completes; the interface comes from the analysis, in scope or file-qualified.
  - Where a call's argument starts (`f(‸`, `f(a, ‸`, `xs |> Task.spawn_all(f, ‸`), the callee's parameters no argument fills yet join the expression candidates as `name: ${1}`, for module, owner, interface, host and imported functions. A parameter with a default ranks first; a required one is offered at an import's rank, since any parameter may be named. Positional arguments before the cursor, the piped value and named arguments anywhere in the call count as filling; a parameter named or typed `self` (each implementation names that one itself) or destructured is never offered by name, and a callee that is not a declared function (a lambda value, a variant) offers no names.
  - `derive ‸` offers the derivable interfaces (`analysis.DerivableInterfaces`), adding the import of one not in scope (`ToJson`), with `Debug` last since every type has it already; `derive ‸ for T` leaves out what the derive lowering would reject for `T` (an interface it already derives or implements by hand, `FromJson` for an enum). `derive Iface for ‸` offers only the file's own top-level types, since a derive in another file is rejected, without those that already derive or implement `Iface` or cannot take it.
  - After `|>`: the functions whose first parameter takes the piped value (owner functions, functions of the interfaces it implements, `Iter`'s for anything iterable, matching functions of the file and its imports), inserted without the first argument. The keyword stages `dbg`, `try`, `if`, `case` and `then` follow, ranked after every function that matches as well; `assert` and `refute`, which a stage cannot be, are not offered.
  - Inside a typed literal's body (`Date"‸"`): the bodies the type's `///` and `//!` lines write (its doc comment, its `impl Literal` block, its inherent `impl` blocks), at most five in file order, as snippets with a tab stop on each run of letters and digits (`${1:2026}-${2:05}-${3:04}`). A type whose docs write none gets nothing. Only a literal opened on the cursor's line is recognized.
  - Trigger characters: `.`; `>` only after `|`; `"` and a backtick only after a type name; `{`, and the `}` an auto-pair plugin adds after it, after a type name (a struct literal's or a struct pattern's fields) or where a value goes (after `:`, `=`, `(`, `,`, `[`, `->`, `return` or at a line's start), opening a list only when the position expects a nominal struct; a `{` typed with no auto-pair plugin is reparsed with the line's open brackets closed; `:` only where a type follows (a parameter, binding or struct field annotation, a return type), not in a struct literal; `,` only for a struct literal's or pattern's next field, whose item then brings the space after the comma.
- [x] Static typed literals (`internal/lsp/literal_eval.go`). An open buffer's typed literals with no `${...}` are evaluated on the VM: the buffer is loaded as its file with one probe function per literal appended (`vmhost.LoadFileSource`), and each probe runs through `vmhost.Program.Evaluate`. A handler that answers `Err(e)` is an Error diagnostic on the whole literal, `Date"2026-13-04" is invalid: InvalidValue("month out of range: 13")`; hover inside the literal shows its value's Debug rendering and its type. A probe is run only when nothing it can reach has an effect (`vm.Machine.Effects`: no crossing outside `vm`'s one list of pure crossings, no app field, Context or scope read or write), under 200,000 steps (calls plus backward branches) and 100 ms each, 2 s per buffer. Evaluation runs in the background after the diagnostics publish and publishes again; results are cached by handler and literal text, a stdlib handler's for the process. Run time is unchanged: the literal still evaluates to its `Err`.
- [x] Workspace index, file watching and cross-file change propagation (`internal/analysis/workspace.go`, `internal/lsp/workspace.go`). Only open documents are analyzed and kept. The scan indexes every other `.nomi` file under the workspace root (its imports and top-level declarations, from a parse), skipping directories named `testdata` or `node_modules` or starting with `.` or `_`, and the stdlib's sources. Auto-import completion, go-to-definition through a selective import and workspace symbols read the index; references and rename analyze only the closed files whose text contains the name, keeping the last 32 such analyses. Closed files get diagnostics from a background pass that analyzes one file at a time, yields to edits and requests, and keeps nothing; a change to a file queues the closed files that import it.
- [x] Workspace symbols: the top-level declarations of open and indexed files, matched by the query's characters in order, ignoring case.
- [x] Background analysis (`internal/lsp/docsched.go`, `rpc.go`). `didChange` stores the text and returns; the document is analyzed 50 ms after the last edit, a newer edit supersedes an older analysis, and diagnostics are published only for the latest text. Requests run concurrently and honor `$/cancelRequest`. Completion and signature help answer at once from the latest text and the last finished analysis; hover, definition, references, symbols, semantic tokens and inlay hints wait (up to 2 s) for the current analysis; rename and code actions fail with `ContentModified` rather than answer from an older one.
- [x] Every `dbg` and every `todo` is published as a Warning (`dbgWarningDiagnostics`, `todoWarningDiagnostics` in `internal/lsp/diagnostics.go`, over `analysis.Dbgs` and `analysis.Todos`, the lists `nomi build` refuses); a `todo`'s message carries its reason.
- [x] Code the compiler cannot lower yet (`internal/lsp/lowering.go`). When a file is opened or saved, and 400 ms after the last edit of a burst of typing, it is lowered in the background as `nomi check` lowers it (`vmhost.CheckLowering`), and each "this call to `f` is not supported yet, so `fn g` cannot run" error is published with the front end's diagnostics, one run per file at a time. A run whose text an edit has replaced by the time it finishes is dropped; the edit's own run follows. Between an edit and its run the last run's diagnostics stay, with that text's ranges; a text the front end rejects reports none. A blocker in another file of the program is reported at the top of the file with its location as related information. A compiler panic during the lowering is one diagnostic at the top of the file. A run checks the program as `nomi check` does, its own front end included: 10 to 35 ms warm on the corpus's files, 32 ms for the largest (523 lines) against the editor analysis's 20 ms, and about 120 ms for the first run in a process, which lowers the stdlib. The lowering proper is under 4 ms of that; the rest is the front end, which a run does not share with the editor's analysis. Every file is checked after edits; none measured near a size where that would need a cutoff. A stdlib file is not lowered.
- [x] Code actions: remove unused or redundant-prelude imports, add a missing import, `source.fixAll`.
- [x] Fill quick fixes (`internal/lsp/code_action_fill.go`), each on its checker error: implement an `impl Iface for T` block's missing required functions (the completion stub's signatures), add a struct or variant literal's missing required fields in declaration order and in the literal's layout, and add a non-exhaustive `case`'s missing arms. Each written body or value is the `todo` expression, so the result checks with no error and each hole is a `todo` warning. In a document that is `nomi fmt` output the edited document is formatted again, so the fix keeps it formatted. Not offered for an `else` binding's non-exhaustive arms.
- [x] Pipe rewrites (`internal/lsp/code_action_pipe.go`, `refactor.rewrite`), on the call or pipeline under the cursor. "Convert to pipe" on a call whose first argument is a call rewrites the chain of first arguments as style.md §1 writes it: the innermost call's first argument leads and each call becomes a stage, `Iter.to_list(Iter.map(xs, f))` to `xs |> Iter.map(f) |> Iter.to_list()`, stacked when there are two or more stages, in parentheses (and on one line) where it is an operand or a `then` lambda's one-expression body, whose body a `|>` would end. A call in a later argument stays nested. "Convert from pipe" folds a pipeline into nested calls: a stage takes the value as its first argument or at its `_`, and a bare `try`, `dbg`, `assert`, `refute`, `case` or `if` stage takes it as its operand, subject or condition. Neither changes evaluation order. Not offered for a pipeline with a `then` stage, a call with a `_` argument (to pipe), a call that is itself a stage, a `.Variant` callee, or a subject that takes its type from its position (`.Variant`, an empty or anonymous literal).
- [x] "Convert to case" and "Convert to if/else" (`internal/lsp/code_action_if_case.go`, `refactor.rewrite`), on the keyword or header (to the body's `{`) of an `if` chain, any `else if` rung, or a `case`. An if chain of conditions becomes a subject-less `case` ending in `_`; `if Pat = v { a } else { b }` becomes `case v { Pat -> a  _ -> b }`; a chain whose every condition is `n == literal` over one name or field read of type Int, String or Codepoint is also offered as "Convert to case on 'n'". "Convert to if/else" reverses each: a subject-less `case`, a two-arm `case` whose first arm is a pattern other than a name, `_` or literal and whose second is `_`, and a literal `case` over a name or field read. An `if` without `else` converts only when its type is Unit, as `_ -> Unit`, and `_ -> Unit` converts back to no `else`; a `_` arm whose body is an `if` continues the chain as `else if`. A branch of one expression (or `return`, `break`, `continue`) with no comments becomes a bare arm, and any other a block arm. Comments are kept, an arm's own moving into its branch block; a conversion that would drop one is not offered. Not offered with a `when` guard, an arm that binds a name in a literal case, a pattern rung after the first, a `case` that is a pipe stage, or a result that would not parse back as the same expression (a struct literal in a condition moved into an `if`).
- [x] "Pattern match on ..." (`internal/lsp/code_action_match.go`, `refactor.rewrite`): on a binding's name whose value is an enum (user enums, `Maybe`, `Result`, generic payloads), a `case` over the name after the binding; on a call that returns an enum, a `case` wrapping the call. The arms are the "Add missing arms" fix's, one per variant, each body `todo`.
- [x] "Generate function" quick fix (`internal/lsp/code_action_generate.go`), read from the analysis and offered while the cursor is in the call: for `foo(a, b)` of an undefined function, `fn foo(...)` after the declaration that calls it; for `Type.foo(x)` on a struct or enum the file declares without type parameters, the function at the end of the type's inherent `impl` block, or in a new block. Parameters are named for plain-name and named arguments (`argN` otherwise) and typed from the arguments, a piped value included; the return type is the call's expected type, none for a discarded statement; the body is `todo`. Not offered when the expected type or an argument's type is unknown (`x = foo(1)` with nothing reading `x`'s type).
- [x] "Call `f()`" quick fix (`internal/lsp/code_action_pipe_stage.go`) on a bare pipe stage: appends `()` to the name the error quotes. Not offered for a `.Variant` stage, which needs its enum named.
- [x] "Write `then` before the lambda" quick fix (`internal/lsp/code_action_pipe_stage.go`) on a lambda pipe stage: inserts `then `. Not offered for a lambda in parentheses, `x |> (|v| ...)`.
- [x] "Extract variable" and "Inline variable" (`internal/lsp/code_action_extract.go`, `refactor.extract`, `refactor.inline`). Extract binds the selected expression, or the innermost call under the cursor, to a name on the line before its statement: the call's function (without `to_`), a field's name, else `value`, numbered when the name is taken. Inline replaces a binding's one read with its expression, parenthesized where an operator needs it, and deletes the binding. Both refuse a move through a lambda body, a case arm, an if branch, the right of `and`/`or`, or a pattern; a move of an expression with a call (or `try`, `dbg`, `assert`, `return`) before an earlier call in its statement, or for inline past the next statement; an expression that takes its type from its position; for inline, an annotated binding, a punned field read, or a read where a name the expression uses means something else. An arithmetic trap is not counted as an effect.
- [x] Formatting (`internal/lsp/formatting.go`), used by Zed's format-on-save.
- [x] Renaming or moving a `.nomi` file or a folder updates its imports (`internal/lsp/file_rename.go`, `workspace/willRenameFiles`, registered for `**/*.nomi` files and all folders). Every open document and every `.nomi` file under the workspace root that imports a moved file gets its import path rewritten, whatever the import's form (path-only, `as` alias, selective, drill-through, in an `import { }` block, or prefixed with the module's own name). A path-only import without `as` binds the file under its last segment, so when that changes, the file's uses of the qualifier change with it (`users.make()` to `people.make()`). A new name that is not an import path segment (a space, a keyword) gets no edit, and nor does an import of a file from another module.

## Formatter
