# Nomi Implementation Status

A contributor dashboard. The spec, [`spec.md`](spec.md),
is canonical for what the language does: **if a feature appears there
without a "Status: not yet implemented" callout, it works.** This file does
not re-list language features. It tracks compiler and tooling milestones, a
punch list of spec sections that are still aspirational, and known defects.

For the forward view (big-ticket initiatives and their order) see
[`roadmap.md`](roadmap.md).

---

## Aspirational language features

Spec sections with a "Status: not yet implemented" callout.

- [§8 Variants as Parameter Types](spec.md) — a struct variant declared inline is not a type: `fn f(r: Rectangle)` and `fn f(r: Shape.Rectangle)` are both `unknown type`. Embedded structs work.
- [§16 Strings: Display for Iters](spec.md) — `"${it}"` or `io.print(it)` on a lazy `Iter` passes the checker, and the program is refused before it runs with a "not supported yet" error rather than a type error.
- [§15 Type Aliases: generic aliases](spec.md) — `typealias Name Target` works; `typealias Name<T> ...` is a parse error at the `<`.
- [§31 CLI surface (`nomi add`, `nomi publish`)](spec.md) — `nomi run`, `nomi build`, `nomi test`, `nomi check` and `nomi fmt` ship; `add` and `publish` wait on the registry question below.
- [§31 Project config: dependencies without a local `replace`](spec.md) — a `require` with no local `replace` is skipped, so a dependency is not fetched through the Go module proxy yet.
- [§31 Registry & Distribution](spec.md) — no Nomi-specific registry. A Nomi module is a Go module, so distribution rides the Go module proxy.
- [§31 Compiler-Enforced Semver](spec.md) — long-horizon. Needs a registry to compare against and a published-API extraction step.

`grep -n "Status: not yet" docs/spec.md` should
match each item above.

## Decisions: intentionally not adopted

- **Interface composition / `extends`.** Multi-bound `where` clauses (`where T: A and B`) cover consumer-side composition, and `embeds` enums cover heterogeneous collections, so an interface-inheritance mechanism would add a second way to say both.
- **Read-only (matchable but not constructable) fields.** `opaque` stays all-or-nothing: a type either exposes its fields for construction, matching and access, or hides all three behind its own functions.

## Known quirks and open defects

- **`continue` in `Iter.loop` retries with the same state.** By design, and stated in the spec's `loop` section. `continue #(i + 1, s)` is a checker error naming the working form (`internal/analysis/continue_value.go`).
- **Programs the checker accepts and the VM cannot run.** The IR builder declines some bodies. `nomi check` lowers the program without running it and reports each declined body that `main` or a test reaches as an error at the expression the builder stopped at (`vmhost.Program.Unsupported`), one per function; a function only a declined function calls is reported once its caller lowers. It takes test files and directories of them, and lowers each case as `nomi test` would; on a stdlib module it lowers the module's `//!` cases. `nomi run` stops with the same errors before its first effect, and `nomi test` reports each case it cannot run as `BLOCKED` with the same error; `NOMI_DEBUG_LOWERING=1` adds the builder's own reason to each as a hint. The language server reports them when a file is opened or saved and 400 ms after the last edit of a burst (`internal/lsp/lowering.go`). Known shapes:
  - `Debug.inspect` of a tuple, record or other structural value holding two instantiations of one generic type, as in `Debug.inspect(#(#Box{v: 1}, #Box{v: "a"}))`. The renderer finds a nested value's Debug body by runtime type name, which every instantiation shares, so the String one is handed to the Int one's body, and the VM stops with a machine limit. This one lowers, so `nomi check` does not report it. One instantiation, or a `List` of either, runs.
  - A payload-free variant of a user generic enum whose type argument nothing constrains, as in `#(Box.Empty, 1)`. There is no instance to build it at.
  - A `case` with list patterns over a list of function values, as in `case xs { [] -> 0  [_, ..rest] -> 1 + size(rest) }` with `xs: List<(Int) -> Int>`. The builder declines it with "this `case` is not supported yet". `Iter` functions over such a list run.
  - A block whose value has a type declared inside that block, as in `w = { struct Loc { n: Int } #Loc{n: 1} }`. The binding is typed at the block-local type, which the builder cannot resolve outside the block, so it declines with "this block is not supported yet". A block that uses the type only inside itself runs.
  - A variant of a user enum imported by name from another file (`import shapes.Shape.Circle`, then `Circle(1)`, or `#Rect{w: 3}` for a struct-shaped one). The qualified `Shape.Circle(1)` runs, and so does a std enum's variant imported by name.
  - A function with a defaulted parameter named as a value at its full type, as in `g = parse` or `g: (String, Bool) -> Maybe<Int> = parse` for `fn parse(s: String, strict: Bool = False)`. The unannotated value keeps its defaults (`g("1")` fills `strict`), and the builder has no value representation that carries them (`internal/irbuild/funcref.go`). A lambda or a partial application (`parse(_)`) runs.
  - A `break` or `continue` in the callback of an iteration function called by a selectively imported bare name, as in `import std/iter.Iter.{find}` and then `find(xs, fn x -> ...)`. The bare call runs std's own body, whose call to the callback has nowhere to send the signal. The owner-qualified `Iter.find(xs, ...)` runs, as does an aliased owner (`It.find`).
  - An `import` at the top of a block that rebinds a name the file already binds to something else, as in `import std/duration.Duration` inside a function of a file that declares its own `Duration`. The builder resolves some names by the file's scope rather than by position, so it declines with "an `import` in a block that rebinds a name the module scope binds differently" (`testImport` in `internal/irbuild/stdtests.go`). A block import of a std file, of a name the file does not bind, runs, including types named through its qualifier (`json.Json.Null`). The same qualifier imported by two blocks from different files declines.
  - A direct call to a named function that uses `break` or `continue`, including from inside a callback lambda (`Iter.map(xs, fn x -> skip_odd(x))`) or from another such function. Pass the function itself as the callback (`Iter.map(xs, skip_odd)`), which runs.
  - An `if` or `case` every arm of which leaves by `return`, `break` or `continue`, as the right operand of `and` or `or`, as in `x > 0 and case x { 1 -> return True  _ -> return False }`. The builder declines it with "this `case` is not supported yet". The same region as an operand that always runs (an argument, an operand of `+`, a struct field, a list item, a pipe's source, the operand of `try`, an `if` condition) runs: the operands before it run, then it leaves, and nothing after it runs.
- **`derive ToJson` and `derive FromJson` in a file that declares its own `Json`.** The derived code names `Json` and `Json.ShapeError`. When the file's scope binds no such name, derived code reaches std's declaration (`synthStdDecls` in `internal/analysis/derive_synthesis.go`); when the file binds it, derived code uses that binding, so a file's own `Json` type makes the derive fail with "undefined type Json.Obj". Shadowing it in derived code only would need the IR builder's name-keyed type tables to resolve by position.
- **A line comment after a payload-free enum variant is a parse error.** `ToJson // note` inside an enum body reports "expected type name, got COMMENT"; a comment on its own line parses.
- **An impl for another file's type is not found when the implementing file declares a type of the same name.** With `impl Html for users.User` in a file that also declares its own `User`, `Html.to_html(#users.User{...})` is rejected with "no impl of `Html` for `User`", and the message does not qualify the name.

## Compiler

- [x] Guaranteed tail calls: `analysis.MarkTailCalls` marks tail positions and the VM runs a tail call by replacing the caller's activation (spec §12).
- [x] Generic functions, types and impls are instantiated per type-argument tuple by the IR builder; existentials dispatch at run time (spec §13).
- [x] The IR builder's own type is `kind` (a tag plus declaration pointers); it holds no Go type text or Go names.
- [x] Interface dispatch selects the body by the declared `self` position's runtime type (`ir.NewDispatchCall`, `internal/vm/dispatch.go`).
- [x] Impl manifest and missing-impl diagnostic: the analyzer records every `#(Iface, T)` pair a program demands, and `DetectMissingImpls` (`internal/analysis/missing_impl.go`) reports a pair no impl supplies.
- [x] Impl coherence: `detectImplCollisions` and the orphan rule `detectOrphanImpls` (`internal/analysis/impl_coherence.go`, spec §13).
- [x] Backtick typed literals whose handler returns a `Result` are checked at compile time (spec §16): the checker types the literal as the `Ok` type (`analysis.RawLiteralType`), the IR builder lowers each site as a lazy cell holding the handler's `Result` and reads its `Ok` payload (`internal/irbuild/irliteralcell.go`), and every load runs each cell's initializer on the VM before the program runs (`vmhost`'s `checkLiterals`, refused by `vm.Machine.Effects` as an editor's evaluation is, under 1,000,000 steps). An `Err` is a compile error at the literal carrying the error's `Display` rendering. `nomi check`, `nomi run`, `nomi test`, the REPL, the tour and the language server's lowering diagnostics share it.
- [x] Nominal identity is (declaring file, name) for structs, enums, distincts and interfaces, through the dispatch key.
- [x] Universal `Debug`: `SynthesizeUniversalDebug` gives every declared type a `Debug` impl; opaque types render `<opaque T>`, and a lazy `Iter` renders `<iter>` without consuming it (spec §16).
- [x] Strong `Comparable` demand: `<`/`>`/`<=`/`>=` on a type with no `Comparable` impl is a compile error.
- [x] Opacity is enforced at the operation, including `Struct.update`.
- [x] Member access is fail-loud: a member a resolved value does not have is a compile error.
- [x] `Iter` is a push protocol (`each_while`, plus the `known_count` default); every algorithm is an `Iter` owner function.
- [x] A declared `Iter<T>` is a value type: struct fields, tuple and record parts, `Some`/`Ok` and enum payloads, parameters, results, list elements and closure captures all hold one, and a collection, Range or user `Iter` implementor passed where an `Iter<T>` is declared keeps its known count and its Debug text.
- [x] `Struct.update` through the universal `Struct` interface.
- [x] Scoped application fields, `boot`, `Context` and `defer` (spec §27, §28): an entry file's `fn boot() -> App` or `fn boot(startup: Startup) -> App` (the parameter may have a default) builds the application value, reads name the application type (`App.field`), the statement `with App.field = v` replaces a field to the end of its block, and each `main` and test is checked against its own boot.
- [x] A `fn main` that returns `Err(e)` fails the run (spec §26): `nomi run`, a `nomi build` executable and the tour print `error: ` and `e`'s Display text (its Debug text when its type has no Display) to stderr and exit 1. `vmhost.Program.Run` answers it as a `*vmhost.MainError`.
- [x] A `fn main` declared to return anything but `Unit` or `Result<Unit, E>` is a checker error at its return type (spec §26), so `nomi check`, `nomi run` and the LSP all report it. A `fn main` that declares parameters is a checker error over its parameter list.
- [x] A body whose return type is `Unit`, written or omitted, may end in a `dbg` observation (`dbg x`, or a pipe ending `|> dbg`): the checker types the body `Unit`, and the builder runs the observation as a statement and returns `Unit`, in top-level, impl and nested functions.
- [x] Structured diagnostics. An analyzer error (`analysis.TypeError`) carries the span it is about, its advice as separate hints and the declarations it refers to as related locations. The parser records every expression's, pattern's and type's extent (`ast.Span`), and an error reported at a point is widened to the token there (`analysis.CompleteSpans`). Converted to spans, hints and related locations: type, argument, element and return mismatches (a return mismatch spans the body's last expression and points at the declared return type), undefined names and unknown fields, types, variants and members (the "did you mean" is a hint), missing struct fields, non-exhaustive `case`, missing impl functions and impl parameter names (both point at the interface function), duplicate declarations (point at the first), missing impls (other demand sites are related locations), the self-render error, the `then`-stage boundary, `_` as a value, and unread bindings and parameters. An error inside a lambda body or a tuple element leaves the enclosing value's type unknown, so it draws no second mismatch.
- [x] `nomi check`, `nomi run`, `nomi build` and `nomi test` print each diagnostic with its source line and its span underlined, then `= help:` and `= note:` lines, coloured on a terminal (`NOMI_COLOR`, `NO_COLOR`). `nomi check --format short`, or `NOMI_DIAGNOSTICS=short` for any command, prints the `path:line:col: message` form instead, with each hint and related location as a `path:line:col: help: ...` or `note: ...` line; that form is also the `Error()` text `vmhost` returns and the message of a `nomi test --format json` file record. `vmhost.Diagnostic` carries the span, hints, related locations and the source line as data. The REPL prints hints under the error.
- [x] Tests: `test`/`group` declarations, `//!` attached tests, `nomi test`, virtual clocks (spec §36). A group names an entry's boot on a `boot` line, and its `setup` value reaches each test through an irrefutable pattern. `group` is a contextual keyword, read as one only at the top level before a string; tree-sitter reads it with an external-scanner token, and the bat and VS Code grammars match the word before a quote at a line start.
- [x] `subtests rows, pattern { body }` and `subtests rows, pattern, name { body }` (spec §36): the body runs once per row as its own function (`internal/irbuild/irsubtests.go`), and a name lowers to a second function of the row that answers its String, called before the body; a failed row reports under the name, and a name that traps fails its row under the rendered row. The VM's `ir.Subtests` (`internal/vm/subtests.go`) catches each row's failed assertion and fails once after the last row with a report listing each failed row (`rt.SubtestsFailure`). In a function returning `Result<_, AssertionFailure>` the combined failure is its `Err`, with the rows in `AssertionFailure.subtests`. A trap in a row is not caught. A breakpoint in the body stops once per row, in a `row` frame under a `subtests` frame. `subtests` is a contextual keyword; tree-sitter reads it with the external scanner's same rule (an expression and a comma follow), and the bat and VS Code grammars approximate it by what follows the word.
- [x] `compiler.check`, `compiler.check_project`, `compiler.run` and `compiler.hover` for tests about the compiler.
- [x] `io.capture(input, run)` runs a function against given stdin and answers its value and everything it printed (spec §36). The redirection rides the calling frame (`rt.Capture`), so tasks inherit it and concurrent captures stay apart; `dbg`, files and runtime diagnostics are not redirected. A `Captured` renders through Debug (`io.inspect`, `dbg`) and may be named as a parameter type (`Captured<Point>`). `Captured.transcript` is in the replay script's form: output lines as written, each line read as four spaces, `> ` and the text, and an indented output line that starts with `> ` escaped as `\>` (`rt.Capture`).
- [x] `io.replay(script, run)` runs a function against a script (`rt.ParseReplayScript`): a line indented past the base column whose text starts with `> ` is input, `>` alone there is an empty line, every other line is output as written, and `\>` after the indentation escapes output that would read as input. It answers an `io.Replayed` that `assert` checks, with a line diff on failure (spec §36). `Replayed` is not generic: the IR builder selects a std `impl Assertable` only for a std struct with a spec row (`internal/irbuild/stdstruct.go`), so it does not carry `run`'s value.
- [x] Concurrency: `concurrent { }`, tasks, channels, `Supervisor`s with restart policies and drain (spec §20). Supervised failures are reported to stderr; there is no in-program failure channel.
- [x] `Decimal`, calendar types, random generation, `Dynamic` and `std/json` with derive (spec §39, §40).
- [x] Irrefutable parameter destructuring (spec §5).
- [x] Default parameter values, including on interface default functions; explicit generic headers and `where` clauses on functions, declarations, derives and impls.
- [x] A struct-shaped variant imported by name (`import std/supervisors.Backoff.Exponential`, then `#Exponential{max_restarts: 3}`) types as its enum and checks its fields, in project and single-file analysis alike.

## Type Checker

Two phases: `BuildTypes` registers and resolves type definitions, `CheckTypes` walks bodies.

### Working

- [x] Function bodies: return types, argument types and counts, named arguments, defaults.
- [x] Operators, pipes, partial application (`_`), string interpolation.
- [x] Operator impls on a generic receiver (`impl Add<T, Box<T>> for Box<T>`), read at the left operand's type arguments, including in generic code.
- [x] Generic call-site unification, consistent type variables across parameters, generic propagation through higher-order functions.
- [x] Function type assignability (spec §5 *Type Annotations*): contravariant parameters and covariant results at every position a function value flows into (`UnifyInto` in `internal/analysis/unify.go`), with the builder's adapter closure doing the conversion (`internal/irbuild/irfuncwiden.go`); joins of two function types require the same type.
- [x] Generic functions used as values (`Iter.each(io.print)`, `Iter.map(xs, ident)`), instantiated against the expected function type with their bounds checked; an unannotated `f = ident` asks for an annotation.
- [x] Bidirectional lambda inference and lambda return unification, including a generic call's parameter that the call's expected type fixes (`f: (Int) -> Int = ident(fn x -> x + 1)`) and a generic struct's field or variant's payload that the expected type fixes (`f: Box<(Int) -> Int> = #Box{v: fn x -> x + 1}`, `Some(fn x -> x)` against `Maybe<(Int) -> Int>`). A lambda parameter with no annotation or default where no function type is expected (an unannotated binding, a tuple or list element, a generic constructor's argument with no expected type such as `h = Some(fn x -> x)`) is `cannot infer type for parameter x`.
- [x] Binding inference, annotated bindings, destructuring bindings.
- [x] Struct, list, vector, set, tuple, map and anonymous-struct literals, with map homogeneity. Every literal but a list's starts with its shape's symbol, `#` for a vector, struct or tuple (`#[1, 2]`, `#Point{x: 1}`, `#(a, b)`) and `%` for a map or set (`%{"k" => v}`, `%[1, 2]`), and a type built on a shape writes its name after the symbol (`#Pair(1, "x")`, `#Path[1, 2]`, `%Kvs{"a" => 1}`, `%Tags["a"]`, `#.Circle{radius: 1.0}`, `%.Obj{}`). The parser knows the shape from the first token, so a struct literal stands in an `if` condition, a `case` subject and a `subtests` name (`checkNamedVectorLit`, `checkNamedSetLit`, `checkNamedTupleLit` in `internal/analysis/shape_literals.go`).
- [x] ASCII codepoint literals (`'a'`, `'\n'`, `'\u{7F}'`), typed as std's `Codepoint` with no import (`analysis.TypeCodepoint`), as values, range ends and patterns at any depth; a malformed one is a lexer diagnostic (`strlit.DecodeCodepoint`), and a `case` over a `Codepoint` that tests literals needs a `_` arm.
- [x] Field accessors (`.name`, `.address.city`, `.0`, spec §8 *Field Accessors*): a function reading a field, typed from the expected one-parameter function type whose parameter is already known (`checkFieldAccessor`, `FileAnalysis.FieldAccessors`), and lowered to a closure over the same projections as `x.name` (`internal/irbuild/irfieldaccessor.go`). An accessor as a pipe stage, with no function expected, or before its parameter type is pinned is an error.
- [x] Target-typed struct literals: a `#{...}` literal with no type name builds the nominal struct its position expects (`a: Address = #{street: …, city: …}`), lowered as `#Address{…}` (`checkTargetTypedStructLit`, `FileAnalysis.TargetStructs`).
- [x] `if`/`case` branch consistency, pattern type checking, and `case` exhaustiveness over enums, tuples, structs, distinct types, lists and vectors (literal, prefix, map and set patterns need a catch-all) (`internal/analysis/exhaustive.go`).
- [x] Vector and set patterns (spec §10 *Vector Destructuring*, *Set Destructuring*): `#[first, ..rest]`, `#[.., last]`, `#[a, ..mid, z]` and the exact `#[a, b]`, split by length for exhaustiveness; `%["admin", ..rest]` tests membership, with elements evaluated as map-pattern keys are (`checkVectorPattern`, `checkSetPattern` in `internal/analysis/shape_literals.go`). The IR builder tests a vector's length and reads elements from either end, and the rest is an O(1) window over the vector's storage (`rt.VectorSlice`, `internal/irbuild/irvectorpattern.go`); a set pattern is `Set.contains?` per element and `Set.remove` for the rest.
- [x] `todo` (spec §5 *Unwritten Code*) has the type its position expects, including an `if` or `case` arm typed by its siblings and a generic result; an unannotated `x = todo` asks for an annotation, and a body holding a `todo` does not report unread parameters (`internal/analysis/todos.go`). It lowers to `ir.Todo`, a trap whose text is `rt.TodoError`'s.
- [x] `Infallible` (spec §15 *Primitive Types*) lowers wherever the checker accepts it: `Result<Int, Infallible>` and any other type containing it is an instance like any other, a function declared to return it runs until it traps, and a construct whose first-evaluated operand is of it never runs past that operand, a call led by one included (`internal/irbuild/irnever.go`, `ir.NeverType`). It implements `Display`, `Equatable` and `Hashable` (`std/results.nomi`), so a type containing it renders, compares and hashes through its interfaces too.
- [x] `try`: operand must be `Result`/`Maybe`, and the propagated value must inhabit the boundary (spec §9).
- [x] `P as name` patterns (spec §10 *Naming the Whole Match*): `ast.AsPattern` in every pattern position, typed as the position, seen through by refutability and exhaustiveness (`ast.WithoutAs`), lowered by binding the matched value on the pattern's success edge (`patternValueTest`, `bindAsNames`), and an `as_pattern` node in tree-sitter. `y as x`, `_ as x` and a name bound twice in one pattern are errors.
- [x] Bindings with `else` (`Pattern = value else { ... }`, spec §10): every path of the else leaves or falls back to the pattern's one payload, else arms plus the pattern are exhaustive, a refutable pattern needs an `else` and an irrefutable one refuses it (`checkPatternBinding`).
- [x] `break`/`continue` context validation (`internal/analysis/iter_sensitive.go`).
- [x] A statement after `return`, `break` or `continue` in the same block is an unreachable-code error (`internal/analysis/unreachable.go`).
- [x] A Display `to_string` or Debug `inspect` that renders its own receiver (`"${foo}"`, `io.print(foo)`, `Display.to_string(foo)`, `dbg foo`, ...) is an error at the rendering (`internal/analysis/self_recursion.go`, spec §16).
- [x] A function every path of which calls itself with the arguments it was given is an error; a tail call counts only when nothing before it on its path calls anything (`internal/analysis/self_recursion.go`, spec §12 *Recursion depth*). Mutual recursion, calls inside lambdas and interface default bodies are not checked.
- [x] `embeds` subtyping, type aliases, generic enum inference, nested type-parameter identity.
- [x] Interface impl signature validation, `open` defaults, `where` bounds.
- [x] `where self: X` on an interface default (`internal/analysis/default_self_bound.go`, spec §13). A default body that needs an interface of `self` other than its own and `Debug` without naming it is an error at the use; an `impl` whose type lacks a default's bound and does not write the function is an error at the block. Under the bound, `self` enters a position typed with the bound interface and takes a bound operator; a `self` passed to a generic function instantiates it at the implementor.
- [x] Interface-typed values are used only at their own interface (`internal/analysis/existential_demand.go`, spec "Implementation: Instantiation and Dispatch"). Using any other interface than the value's own or `Debug` (`==` compares structurally) is an error at the use with a hint writing a type parameter bounded by both. An interface-qualified call on such a value whose signature needs the implementor's own type beyond the receiver (a `self` result, a second `self` argument, a parameter holding `self`), or of a function with no `self` parameter that nothing names an implementor for, is an error at the call.
- [x] Interface defaults whose signature names `self` beyond the receiver (a `self` or `#(self, self)` result, `List<self>`, no `self` parameter) run per implementor, declared in the same file or another (`internal/irbuild/impl.go` `inheritedDefaultSig`).
- [x] `Distinct<T>` and `self(...)` in interface defaults (`internal/analysis/distinct_self.go`, spec §13 *Defaults over distinct types*). Every distinct type is a `Distinct<T>` for the type it wraps; under `where self: Distinct<T>` (T concrete or an interface type parameter) a default takes `self` apart with `self(p)` in a parameter, `case` arm or binding, and builds one with `self(x)`, `x |> self()` or `self` as a function value. The builder lowers each as the implementor's own destructuring and constructor (`gen.selfDistinct`). An opaque type implemented outside its file does not get such a default and writes the function. Every value the checker types as the default's `self`, or as a type holding it (`List<self>`, `Maybe<self>`, a lambda's parameter or result, a binding, a pipe stage), lowers at the implementor's kind, so `Iter.map(xs, fn c -> Temperature.unit(c))` over `self` values runs; a value annotated with the interface's name stays an existential.
- [x] Type-parameter uses need a bound (`internal/analysis/type_param_bound.go`, spec "Interface Bounds on Generics"). An interface a generic body needs of its own type parameter, other than `Debug` and `==`, must be one of the parameter's bounds; otherwise it is an error at the use with a hint showing the `where` clause.
- [x] Visibility consistency (§3) and naming conventions (§4).
- [x] Unused imports, redundant prelude imports, unused bindings and parameters are errors.
- [x] Cross-file calls are checked like same-file calls.
- [x] `==`/`!=` over an `Iter`, a function value, or a value holding one is a compile error naming the part (spec §30).
- [x] A `Set` element or `Map` key with no equality (an `Iter`, a function value, or a value holding one) is a compile error at the literal, call or pipe that builds the collection (`internal/analysis/equality_domain.go`).
- [x] A pipe stage is a call: a bare name (`x |> f`, `x |> io.print`, `x |> Ok`) is an error that names the call to write, and a `.Variant` stage asks for its enum (`internal/analysis/pipe_stage_call.go`, spec §6). The `then` stage (`x |> then fn v -> ...`) and the keyword stages are the stages that are not calls; a bare lambda stage is an error that names the `then` to write, with a quick fix that inserts it.
- [x] A type name is not a value and not a function: `f = Int`, `Iter.map(xs, String)`, `x = calendar.Date`, `Int("4")`, `Int(id)`, `String(4)` and `Dir(1)` are errors at the name, with a hint naming the conversion where there is one, or the destructuring (`Id(n) = id`) when the argument is a distinct (`internal/analysis/type_name_value.go`, spec §15 *Distinct Types*). A struct's record call form, a distinct's construction, variants, zero-sized types and `Type<T>` witnesses are unaffected.
- [x] A function value never fills a generic parameter whose shape is not a function, or the reverse: `Maybe.with_default(f, 0)` with `f: (String) -> Maybe<Int>` is an argument mismatch (`internal/analysis/func_value_shape.go`).
- [x] Only a function value can be called: `1()` or calling a tuple, list or struct value is an error at the callee (`` `Int` is not a function ``).
- [x] A generic argument whose outermost type differs from its parameter's is a mismatch even while the parameter's type variables are unsolved: `Set.size({})` (Unit), `List.head("x")` and `Maybe.some?(4)` are errors (`headDiffers` in `internal/analysis/func_value_shape.go`).
- [x] A file-qualified call to an inherent or impl function (`strings.trim(s)`) is an error whose hint names the owner form (`String.trim(...)`).

## LSP

### Implemented

- [x] Diagnostics, document symbols, hover, signature help, semantic tokens, inlay hints. A diagnostic's range is the error's span (a parse error's is its token); its hints follow the message as `help:` lines, and its related locations are `relatedInformation` when the client declares `publishDiagnostics.relatedInformation`, `note:` lines of the message otherwise. The quick fixes (implement missing functions, add missing fields or arms, generate function, remove or add an import) match a diagnostic by its range, so a client that sends only the diagnostics under the cursor gets them anywhere in the span. A related location in a standard library file is left out: the analysis has no path for it. A document symbol's range is its declaration's extent (`ast.Span`, which the parser records: from the first token after any doc comment or `//!` test through the last), and its selection range is the name, for declarations, `test`s and test groups and their members. A semantic token on a `//!` attached-test line carries the `attachedTest` modifier, which the Zed extension's `semantic_token_rules.json` uses to keep attached tests dimmed; Neovim and VS Code find attached tests themselves and leave the modifier unstyled.
- [x] Inlay hints (`internal/lsp/inlay_hints.go`, `pipe_hints.go`): parameter names, the types of unannotated bindings and lambda parameters, and the type a stage line of a multi-line pipeline produces (a pipeline with a `|>` that starts a line) where it differs from the line above's. - [x] Completion (`internal/lsp/completion*.go`). The request reparses the file with a sentinel identifier at the cursor (`parser.ParseResilient`, so a half-typed body still completes) and reads the position from the tree; names, scopes and types come from the analyzed snapshot, possibly one edit old with positions mapped into it, and nothing is re-analyzed per request. In a statement the checker never saw, an expression's type is read from symbols, and a generic call's result is instantiated by unifying its parameter types with its arguments' types under the file's impl tables, the checker's own unifier (`first(points).` offers Point's fields, and `Iter.map(ns, to_point) |> Iter.to_list() |> ` offers what takes a `List<Point>`).
  - By position: declaration keywords at the top level, statement keywords at a statement start, operand keywords and names in an operand, only types in a type annotation, variants in a pattern, nothing in a string, a comment or a new name. A string's `${...}` (in a plain, triple-quoted or typed literal, closed or not) is an operand; a raw string's body is text.
  - A keyword that opens a block inserts its shape as a snippet, at the top level, a statement start or an operand (`completion_keywords.go`): `if ${1:condition} {…}`, `case ${1:value} {…}`, `fn ${1:name}(${2}): ${3:Unit} {…}`, `struct`, `enum`, `impl`, `test` (with `assert $0`) and `group`, plus an `if else` item beside `if`. The shape replaces the bare keyword's item, so each keyword is listed once; without snippet support the item inserts the bare keyword and `if else` is not offered. A `//!` line, a string's `${...}` and a pipe stage keep the bare keyword.
  - A `//!` group is a test body: a name bound on an earlier line of the group is in scope with its type on its later lines (`u.` offers `u`'s fields), also while the line being typed does not parse, since the editor's resilient parse turns that line into an error node and keeps the group. A group's bindings reach neither another group nor the declaration.
  - `Owner.`: a type's inherent and interface-impl functions, an enum's variants, an application type's fields (only those after `with App.`); `Display.` an interface's functions and the owner functions declared on it (`Iter.map`); `T.` a type parameter's bounds' functions; `server.` a user or stdlib file's public members; `value.` the fields of the value's type and nothing else.
  - `import ` and `import std/` complete paths; `import x.{` the file's unselected public names.
  - A parameter name in a `fn` signature (module, impl, interface or host function, not a lambda) offers `name: Type` for each type in scope, named by the type's snake_case spelling (`game: Game`, `user_id: UserId`), so the list a client gets at the name's first letter already holds it; the type the whole typed name spells ranks first. After `name:` that type ranks first among the types. A generic type inserts a snippet with a tab stop per type argument (`List<${1}>`). The signature is read from the tokens, so an unclosed one (`fn slay(game, mon`) completes too. A type position offers only the modules the file imports as qualifiers, not the file's own module name or `prelude`.
  - Items carry the hover signature as detail and the doc comment on `completionItem/resolve`; calls insert as snippets with placeholders for required parameters only, falling back to plain text without client snippet support; every item replaces the whole word, in UTF-16 columns.
  - The expected type (the checker's recorded `ExpectedTypes`, or the slot's declared type while the statement does not parse) limits `.` to the expected enum's variants and ranks fitting items first, then locals, the file's names, imports, and names that need an import.
  - Where the expected type is a one-parameter function over a struct (`Iter.map(users, .‸)`, `users |> Iter.map(.address.‸)`, `get: (User) -> Int = .‸`), `.` offers the fields the field accessor can read, with a generic call's type parameters solved from its other arguments and the piped value (`FileAnalysis.CallArgParamType`). Hover and go-to-definition on an accessor's segment show and reach the field.
  - Where the expected type T is a nominal type (a struct, enum, distinct, opaque or host type, not a primitive, a List or an interface), an operand also offers the ways to build one (`completion_constructors.go`): T's inherent owner functions that return T and take no T, as owner-qualified calls (`Duration.seconds(${1:n})`, `Map.empty()` against `Map<String, Int>`); at `Maybe<X>` or `Result<X, E>`, X's functions returning exactly that (`Date.parse(s)` where `Result<Date, Error>` is expected, not where a plain `Date` is); and, when T implements `Literal`, a typed literal from its docs' first example (`Date"2026-05-04"`). They match on the function's name (`no` finds `Instant.now()`), rank with the fitting items after locals, and an owner the file does not name adds its import as auto-import does. A struct is not offered as a `#T{...}` literal; its name is, and `{` after `#T` then completes its fields.
  - Names from unimported stdlib and project files (a file object, a public type, `io.read_line`) add their import on accept, merged into an existing import; prelude names are never imported again.
  - A struct literal offers its unwritten fields, an update (a spread, or a bare-`..` literal such as `#{.., ‸}` at a field under one) in declaration order since it needs none. A `#{‸}` or `#{ci‸}` with no type name offers the fields of the nominal struct its position expects (a struct literal's field, an annotated binding, an argument, a return or block tail, a typed list item, a case arm, a patch's field) and nothing where none is expected (a map, an interface, no expected type); a plain `{` is a block and offers no fields. A word right after a field's value with no `,` (`#{..p, address: #{}‸}`) is not offered the literal's fields. A struct pattern offers the fields it does not name yet, as bare names (the punned `#Point{x, y}`), in a case arm, a destructuring binding, an `assert` pattern, a parameter, a variant's payload or a tuple, with the type read from the pattern's head or its position (an unclosed one in a case arm too; an unclosed one at a statement start reads as a struct literal until its `}` and `=` are written); a case over an enum offers all its missing arms in one snippet; a `group` offers `clock`, `boot`, `setup`, `test` in grammar order and its entry boots after `boot`. After `#{..m, ` over a map, the slot is an entry's key and offers values, not field labels.
  - At a line start in an `impl Iface for T` body, or after `fn ` there, the interface's functions the block does not define, each inserting its whole declaration with an empty body: `self` spelled as the header spells `T`, a lone self parameter named by `T`'s snake_case spelling (`item: Item`, `box: Box<T>`), other parameters and defaults as the interface declares them (an impl must keep their names). An interface type argument comes from the header (`impl Add<Days, Date>`) or from a function the block already defines; an unknown one is a linked placeholder (`(${1:T}) -> Bool`). Required functions come first, then the `open` defaults, labelled `default:`; a final default is never offered. With two or more required functions missing, a first item writes them all. Read from the tokens, so an unclosed block completes; the interface comes from the analysis, in scope or file-qualified.
  - Where a call's argument starts (`f(‸`, `f(a, ‸`, `xs |> Task.spawn_all(f, ‸`), the callee's parameters no argument fills yet join the expression candidates as `name: ${1}`, for module, owner, interface, host and imported functions. A parameter with a default ranks first; a required one is offered at an import's rank, since any parameter may be named. Positional arguments before the cursor, the piped value and named arguments anywhere in the call count as filling; a parameter named or typed `self` (each implementation names that one itself) or destructured is never offered by name, and a callee that is not a declared function (a lambda value, a variant) offers no names.
  - `derive ‸` offers the derivable interfaces (`analysis.DerivableInterfaces`), adding the import of one not in scope (`ToJson`), with `Debug` last since every type has it already; `derive ‸ for T` leaves out what the derive lowering would reject for `T` (an interface it already derives or implements by hand, and `Variants` unless `T` is an enum whose variants carry no data). `derive Iface for ‸` offers only the file's own top-level types, since a derive in another file is rejected, without those that already derive or implement `Iface` or whose shape it does not take (`analysis.DeriveTakes`).
  - After `|>`: the functions whose first parameter takes the piped value (owner functions, functions of the interfaces it implements, `Iter`'s for anything iterable, matching functions of the file and its imports), inserted without the first argument. The keyword stages `dbg`, `try`, `if`, `case` and `then` follow, ranked after every function that matches as well; `assert` and `refute`, which a stage cannot be, are not offered.
  - Inside a typed literal's body (`Date"‸"`): the bodies the type's `///` and `//!` lines write (its doc comment, its `impl Literal` block, its inherent `impl` blocks), at most five in file order, as snippets with a tab stop on each run of letters and digits (`${1:2026}-${2:05}-${3:04}`). A type whose docs write none gets nothing. Only a literal opened on the cursor's line is recognized.
  - Trigger characters: `.`; `>` only after `|`; `"` and a backtick only after a type name; `{`, and the `}` an auto-pair plugin adds after it, after a type name (a struct literal's or a struct pattern's fields) or where a value goes (after `:`, `=`, `(`, `,`, `[`, `->`, `return` or at a line's start), opening a list only when the position expects a nominal struct; a `{` typed with no auto-pair plugin is reparsed with the line's open brackets closed; `:` only where a type follows (a parameter, binding or struct field annotation, a return type), not in a struct literal; `,` only for a struct literal's or pattern's next field, whose item then brings the space after the comma.

- [ ] Go-to-definition on a function a type inherits from an interface default (`Dog.shout(rex)` where `shout` is `Speech`'s default) returns nothing.
- [ ] Sibling files read from disk parse with `parser.ParseWithRecovery`, not `ParseResilient`, so a syntax error inside one of their functions drops that whole function from an open file's project analysis.

## Debugger

- [x] `nomi dap` (`internal/dap`): a Debug Adapter Protocol server over stdio that runs the program in process on a debug machine. Launch `mode: "run"` runs `main` of a file, or of a project whose `nomi.toml` lists one entry point; `mode: "test"` runs a file's tests, or one by `line` as `nomi test --line` selects it, and reports them as `nomi test` does (`format: "json"` for the records `--format json` prints).
- [x] Line breakpoints, answered with where they landed (the next line with a statement), stopping once per pass over the line; step over, in and out at statement granularity (a pipeline is one statement for step over); pause; `stopOnEntry`.
- [x] Exception stops: traps, failed assertions and an `Err` from `main` (filters on by default), and a failed task's fault reaching its `Task.await` (off by default).
- [x] Threads: the main thread and each task, named by its spawn site (`task at worker.nomi:12`). When two threads reach a stop at once, the second is reported on the next resume, and a thread blocked in a call into Go (`Task.await`, `io.read_line`) shows its stack from that call. Pause stops at once when every thread is blocked in such a call.
- [x] Evaluation (`internal/dap/evaluate.go`, `vmhost.Program.CompileExpr`, `vm.Scope.Run`): watches, hovers, the debug console and copy value. An expression is checked and lowered as a function appended to the frame's file, whose parameters are the frame's variables it names at their recorded types, and runs on a view of the stopped machine that links its lowering without changing the machine. A type the frame's file cannot name (declared in a file it does not import) is imported from the one program file that declares it `pub`, at the start of the first line so no line moves. In a standard library frame the expression is a file of its own beside the entry: it sees the frame's variables, the prelude, the frame's std module's `pub` types, and what it imports, but not the std file's private declarations. One that can reach an effect is refused unless it ends with `// allow effects` (never on hover); every evaluation runs under 1,000,000 steps and 2 s. A variable or a field path on one is read from the frame without compiling. Results with children are trees.
- [x] Conditional breakpoints (a Bool condition), hit counts (`N`, `== N`, `>= N`, `> N`, `<= N`, `< N`, `% N`, counting the passes whose condition held) and logpoints (`{expr}` parts rendered as the variables pane renders them; `{{` and `}}` are braces). A condition or part that does not compile where the breakpoint lands leaves it unverified with the error; a condition that fails as it runs stops with the reason.
- [x] The Pipeline scope: in or just after a `|>` chain, each stage by its source with its value once it has run (the builder's `ir.Func.Pipes`). A lazy `Iter` stage shows the first 100 elements it passed on once a later stage forced the pipeline, recorded by an `opTap` a debug machine compiles after the stage.
- [x] Captured output scopes (`internal/dap/captured.go`, `vm.Debugger.Captured`): a frame inside one or more `io.capture` or `io.replay` calls has a scope for each, innermost first, named by the call and its site (`Captured output (io.replay at bank.nomi:32)`). It holds `output` and `transcript` as Strings whose children are their lines (paged), and for a replay the transcript in the two-column form, without trailing whitespace, even for a script with no input, the script's input lines read and still to come, and `diverged` with the first script line the transcript already differs from. It reads the capture the frame's rt frame carries (`rt.Capture.View`) and runs nothing. The call's site is the caller of the innermost activation outside the capture; a tail call to `io.replay` shows its caller's site, and a task spawned inside the call names none.
- [x] A test launch's own output (`io.print`, `io.write`, `io.inspect`, `dbg` in the case, outside any `io.capture`) reaches the console as the case writes it (`vmhost.Program.StreamTestOutput`), so a paused test shows what it printed so far; the text report then leaves it out under the case's line, and JSON records still carry it. `nomi test` is unchanged.
- [x] Restart frame: the frame runs again from its first statement with the same arguments, and the console says effects already performed are not undone. Refused, with the reason, below a call from Go (an `Iter.map` callback), for a frame a tail call replaced, while the thread is blocked in Go, and with deferred calls pending.
- [x] Step back and reverse continue (`internal/vm/debugtravel.go`, `supportsStepBack`): a debug machine counts the statements it runs and records every crossing out of the machine whose answer a replay cannot compute (input, the clock, randomness, timers, files, std/compiler's hosts) with its result and statement; a read an `io.capture` or `io.replay` answers runs again instead, so the capture's transcript and script position replay too; output crossings are recorded for checking. Going back abandons the run and replays the program from its start on a fresh machine, answering each crossing from the recording and checking it is the same call at the same statement, printing nothing and reading nothing, to the target, then goes live once it passes the furthest point reached. Step back is reverse next (the latest earlier statement at the same call depth or shallower; from a fault, the start of its statement); reverse continue goes to the latest earlier breakpoint stop, its condition and hit count as they evaluated on that run (a hit count counts from the program's start), or to the first statement. A restart frame is replayed as history; one in recorded history cuts the recording there. A replay that differs from its recording stops as an exception ("Replay diverged") and goes on live. Going back from statement N re-runs the statements before the target (no checkpoints); a reverse continue after breakpoints changed first scans to N. A recorded crossing costs about 56 bytes beside its value, which is shared, and the recording holds 1,000,000 crossings before step back turns off, saying so.
- [x] Function breakpoints (`internal/vm/debugfunc.go`, `supportsFunctionBreakpoints`): a name stops at the first statement of every activation of the functions it names, a recursive or tail call included. Names are spelled as the call stack names frames: `transact`, `Account.deposit`, `Card.to_string` for an impl's function, with type arguments to pick one instance (`ident<Int>`), each optionally qualified by its file's name (`tiny_bank.transact`); an interface method (`Display.to_string`) names every impl of it, and a generic function stops in every instance. Lambdas are not nameable. A condition and a hit count work as on a line breakpoint, the condition checked against the first matching function's parameters. An unknown name is unverified, listing up to five close names. Reverse continue stops at a function breakpoint's earlier entries as at a line breakpoint's.
- [x] Step into target (`internal/vm/debugtarget.go`, `supportsStepInTargetsRequest`): `stepInTargets` lists, for the innermost frame of a stopped thread, the calls its statement makes that a step in could enter, in the order they are entered, each ranged over its call or lambda: direct calls (named as the stack names them), dispatched calls (by interface method), a call through a variable holding a known function, and a lambda or named function passed to a call or an `Iter` operation (`Iter.map(fn n -> ...) callback`). Host calls are not targets, and with just my code nothing in the standard library is (a callback passed to it is). A repeated label carries the call's ordinal (`double (call 2)`). `stepIn` with a `targetId` stops at the target's first statement, breakpoints and exceptions first; when the statement finishes without entering it, the thread stops where step over would and the console says so. The targets are read off the IR from the frame's statement mark to the next mark that is not a pipe stage.
- [x] Go to a variable's binding: each local, pipeline stage and captured-output value carries a DAP `declarationLocationReference`, and the `locations` request answers the name's source range: a parameter's name, the `name` of `name = ...`, a name inside a destructuring or pattern, a loop's state name, and for a closure's captured value the binding it captured (`ir.Var.Decl`). A pipeline stage's is where it is written, and a captured-output value's the `io.capture` or `io.replay` call. go-dap v0.12.0 has neither the field nor the request, so `internal/dap/protocol.go` defines them over its types.
- [x] Inline values: `nomi-lsp` answers `textDocument/inlineValue` with a variable lookup at each parameter and local of the paused function, up to the paused line.
- [x] The logical call stack with absolute source paths, across Iter callbacks (`main`, `Iter.map`, the lambda); a tail call's frame is followed by a `(tail call)` label; frames in the standard library and Go-driven operations are `subtle`.
- [x] Locals by Nomi name and type, the binding in force for a shadowed name, as a lazy tree (`rt.Inspect`): struct fields, variant payloads, list, vector and set elements paged (`indexedVariables`), map entries.
- [x] Just my code: step in passes through the standard library to the user's next statement; `justMyCode: false` steps into it.
- [x] Program input and output through the editor's terminal (`runInTerminal` and the hidden `nomi dap-terminal` stub, over a Unix socket) when the launch's `console` is `integratedTerminal`, the default for a program; otherwise output events, and a program reading input is told the debug console has none.
- [x] VS Code: the `nomi` debug type, launch.json snippets, F5 on the active file, Debug lenses and commands, inline values, its own Step Back and Reverse Continue buttons, function breakpoints from the Breakpoints view's **+**, and Step Into Target (the editor's context menu while paused). VS Code 1.140 keeps a variable's `declarationLocationReference` but offers no command that opens it. Neovim: an nvim-dap adapter registered without loading nvim-dap, Debug lenses, `:NomiDebug` (with `back`, `reverse`, `target` and `break <function>`), `<leader>dh` and `<leader>dH`, nvim-dap's tag jump (`Ctrl-]`) from a variable in its widgets to its binding, and neotest's `dap` strategy. Zed: the `Nomi` debug adapter in the extension and a locator that gives each `nomi run` and `nomi test` task a debug entry; Zed's `debugger: step back` action works when an adapter supports it, and Zed has no reverse continue. Zed 1.2 sends no `stepInTargets`, `setFunctionBreakpoints` or `locations` request, so those three are not available there. Helix: a `[language.debugger]` block with run and test templates; Helix has no step back, step into target, function breakpoints or go-to-binding.

### Not yet implemented

- Step back in a program that starts a task, uses `concurrent`, a supervisor or a channel: it turns off at the first one, saying why. A replay cannot reproduce how tasks interleave.
- A step back's replay runs to its target without stopping; pause does not interrupt it.
- An expression evaluated with `// allow effects` runs outside the recording: what it reads or writes is not replayed.
- A type the frame cannot name that no program file, or two, declare `pub` (a private type of another file) still does not compile in an expression.
- Programs with Go bindings (`gopkg`): `nomi dap` refuses to launch them, since they run in a generated wrapper process.
- A test launch names one file; a directory of test files is not supported.
- Attaching to a running process or a `nomi build` executable.
- The Helix debugger block is checked as TOML but has not been run in Helix; the Zed adapter is built and unit tested but has not been run in Zed.

## Formatter

- [x] `nomi fmt`: zero-config Wadler pretty-printer, 100 display columns (grapheme clusters, a wide character counting two), 4-space indent, idempotent and semantics-preserving (property tests over `tests/` and `std/`). `-w` writes, `-l` lists changed files, no path reads stdin. `-d` prints each changed file's formatted text under a `--- path` line; it is not a unified diff yet.
- [x] String escapes: one table (`nomi/strlit`) backs the lexer's decode and the formatter's encode; unknown or malformed escapes are compile errors.
