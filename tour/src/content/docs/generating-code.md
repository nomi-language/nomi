Some code is better written by a program than by hand: an enum for every
value a data file lists, a lookup function for every row of a table, a typed
function for every SQL query. Nomi has no macros. A library that writes code
for you ships a **tool**, an ordinary Nomi program that reads your data and
writes ordinary `.nomi` files. You run it, read what it wrote, and commit
it like any other file of your project.

The next chapter, [Databases](/databases/), shows the biggest example,
sqlkit's `nomi tool sqlkit generate`, which writes typed functions for SQL.
This chapter writes two small generators of its own.

## A tool

A cafe lists the choices it offers in a file, one line per enum:

```text
Size: small medium large
Roast: light medium dark
```

A tool turns each line into an enum. A tool is a program in a module's
`tools/` directory, with a `fn main` like any program. Here it is the
cafe's own, `tools/choices.nomi`:

```tree
cafe/
├── go.mod
├── nomi.toml
├── enums.choices
├── enums.nomi
├── main.nomi
└── tools/choices.nomi
```

`nomi tool cafe choices` runs `tools/choices.nomi` from the module `cafe`,
with the current directory as its working directory, and with the same
access to files, the network and output that `nomi run` gives a program.
It reads `enums.choices` and writes `enums.nomi`, which `main.nomi` imports
like any other file. The tool builds each enum from a triple-quoted string,
so its template reads like the code it writes.

This example runs the tool before each run, as you would after an edit. Add
a size, or a line of your own, and run it again: the generated file's tab
shows the change.

```nomi-run manual tool:cafe/choices
// FILE: enums.choices
Size: small medium large
Roast: light medium dark

// FILE: main.nomi
import {
    std/io
    enums.{Roast, Size}
}

fn ounces(size: Size) -> Int {
    case size {
        Size.Small -> 8
        Size.Medium -> 12
        Size.Large -> 16
    }
}

fn main() {
    io.print(ounces(Size.Medium))
    io.print(Roast.Dark == Roast.Dark)
}

// FILE: enums.nomi
// Generated by `nomi tool cafe choices` from enums.choices. Do not edit.
/// The choices of `Size` in enums.choices.
pub enum Size {
    Small
    Medium
    Large
}

/// The choices of `Roast` in enums.choices.
pub enum Roast {
    Light
    Medium
    Dark
}

// FILE: tools/choices.nomi
// `nomi tool cafe choices`: write enums.nomi from enums.choices, one
// enum per line. A line `Size: small medium large` declares
// `pub enum Size` with the variants `Small`, `Medium` and `Large`.
import {
    std/fs
    std/io
}

fn main() -> Result<Unit, String> {
    text = fs.read_text("enums.choices") |> Result.map_err(fn e -> "enums.choices: ${e}")?

    enums =
        String.split(text, "\n")
        |> Iter.with_index()
        |> Iter.filter(fn #(_, line) -> String.trim(line) != "")
        |> Iter.map(fn #(i, line) -> enum_of(i + 1, line))
        |> Result.collect()?

    body = String.join(enums, "\n\n")

    source = """
        // Generated by `nomi tool cafe choices` from enums.choices. Do not edit.
        ${body}
        """

    fs.write_text("enums.nomi", source + "\n") |> Result.map_err(fn e -> "enums.nomi: ${e}")?
    io.print("wrote enums.nomi")
    Ok(Unit)
}

// The enum line `number` declares.
fn enum_of(number: Int, line: String) -> Result<String, String> {
    #(name, words) = case String.split(line, ":") |> Iter.to_list() {
        [name, words] -> #(String.trim(name), String.words(words))
        _ -> return Err("enums.choices:${number}: write `Name: first second third`")
    }

    if Some(word) = Iter.find(words, fn w -> not is_snake_case(w)) {
        return Err("enums.choices:${number}: `${word}` is not a snake_case word")
    }

    variants = words |> Iter.map(fn w -> "    ${String.pascal_case(w)}") |> String.join("\n")

    Ok(
        """
        /// The choices of `${name}` in enums.choices.
        pub enum ${name} {
        ${variants}
        }
        """
    )
}

fn is_snake_case(word: String) -> Bool {
    word != "" and Iter.all(word, fn c -> String.contains("abcdefghijklmnopqrstuvwxyz_", c))
}

// FILE: go.mod
module cafe

go 1.27.0

// FILE: nomi.toml
[module]
name = "cafe"
entry_points = ["main"]
```

12
True

`enums.nomi` starts with a comment saying it is generated and must not be
edited by hand, since the next run of the tool would undo the edit. Change
`enums.choices` and run the tool instead.

The tool is the place to check its input. Change `small` to `Small` in
`enums.choices` above and run the example. The tool stops with an error
that names the line, and it writes nothing:

```console
$ nomi tool cafe choices
error: enums.choices:1: `Small` is not a snake_case word
```

The tool's `main` returns an `Err`, which `nomi tool` prints after
`error: `, as `nomi run` does.

## Keeping generated files current

This second tool turns each CSV file under `data/` into a lookup function.
The header names the key and the value with their types, and each row maps
a key to a value:

```csv
code: String,basis_points: Int
usd,9200
gbp,11700
jpy,61
```

The generated `tables.nomi` holds a function `rates(code: String) ->
Maybe<Int>` with one `case` arm per row. A cell is written into the code as
it is, so a rate of `92.00` would be a type error in the generated code,
which `nomi check` reports.

Generated files go stale when an input changes and nobody runs the tool
again. This tool guards against that in two ways. It records a SHA-256
digest of its inputs (`hash.sha256_hex` from [std/hash](/reference/hash/))
at the top of each file it writes:

```nomi
// Generated by `nomi tool csvdata generate` from data/*.csv. Do not edit.
// inputs sha256: ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e
```

The first guard is `--check`: the tool writes nothing and fails when a
file differs from what it would write. Run that command in an automated
check:

```console
$ nomi tool csvdata generate --check
error: tables.nomi, tables_test.nomi would change: run `nomi tool csvdata generate`
```

The second guard is a test, which uses the digest. The tool writes
`tables_test.nomi`, whose test computes the digest of the inputs again and
compares it with the one in the header. A plain `nomi test` then fails when
a CSV file changed after the tool last ran. A test resolves a relative path
under its module root, so it reads the same files wherever `nomi test` runs:

```nomi
// Generated by `nomi tool csvdata generate` from data/*.csv. Do not edit.
// inputs sha256: ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e
import csvdata

test "generated tables are current" {
    assert csvdata.inputs_digest("data")
        == Ok("ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e")
}
```

The cafe's tool serves the cafe alone. To share a generator between
projects, put it in a module of its own, as sqlkit is
([Databases](/databases/)). Here the generator is the project
`csvdata`, and `rates` is a project beside it that uses it:

```tree
projects/
├── rates/
│   ├── go.mod
│   ├── nomi.toml
│   ├── data/rates.csv
│   ├── tables.nomi
│   └── tables_test.nomi
└── csvdata/
    ├── go.mod
    ├── nomi.toml
    ├── csvdata.nomi
    └── tools/generate.nomi
```

In `rates/`, `nomi add` adds the module by its directory, as it adds any
dependency. Any other project adds it the same way.

```console
$ nomi add ../csvdata
added csvdata from ../csvdata (module csvdata; import csvdata)
```

`nomi tool csvdata generate`, run in `rates/`, then runs the module's
`tools/generate.nomi` there, so it reads and writes the files of `rates`.

The digest is `csvdata.inputs_digest`, a function of the module, so the
tool and the test compute it the same way. This example holds both
projects and runs in `rates/`: the tool, then the test. Edit a rate in
`rates/data/rates.csv` and run it: the tool rewrites `tables.nomi` and
`tables_test.nomi`, and the test passes. Run it once more and the tool
finds both files up to date.

```nomi-run manual tool:csvdata/generate
// FILE: rates/data/rates.csv
code: String,basis_points: Int
usd,9200
gbp,11700
jpy,61

// FILE: rates/tables_test.nomi
// Generated by `nomi tool csvdata generate` from data/*.csv. Do not edit.
// inputs sha256: ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e
import csvdata

test "generated tables are current" {
    assert csvdata.inputs_digest("data")
        == Ok("ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e")
}

// FILE: rates/tables.nomi
// Generated by `nomi tool csvdata generate` from data/*.csv. Do not edit.
// inputs sha256: ff6bb7acf34bfd46759e72257f8e01131f1fecfe3f9660edc20f6467999dd93e
/// The `basis_points` of each `code` in data/rates.csv.
pub fn rates(code: String) -> Maybe<Int> {
    case code {
        "usd" -> Some(9200)
        "gbp" -> Some(11700)
        "jpy" -> Some(61)
        _ -> None
    }
}

// FILE: rates/nomi.toml
[module]
name = "rates"

// FILE: rates/go.mod
module rates

go 1.27.0

require csvdata v0.0.0

replace csvdata => ../csvdata

// FILE: csvdata/csvdata.nomi
//# Lookup tables from CSV files. `nomi tool csvdata generate` writes
//# tables.nomi from the module's data/*.csv files, a function per file,
//# and tables_test.nomi, whose test calls `inputs_digest` to see that the
//# files have not changed since.

import {
    std/fs
    std/hash
}

/// The SHA-256 digest of the CSV files directly in `dir`, each path and
/// text in name order: what tables.nomi's header records.
pub fn inputs_digest(dir: String) -> Result<String, String> {
    paths = fs.glob("${dir}/*.csv") |> Result.map_err(fn e -> "${dir}: ${e}")?

    texts =
        paths
        |> Iter.sort()
        |> Iter.map(fn path -> {
            fs.read_text(path)
            |> Result.map(fn text -> "${path}\u{0}${text}\u{0}")
            |> Result.map_err(fn e -> "${path}: ${e}")
        })
        |> Result.collect()?

    Ok(hash.sha256_hex(String.to_bytes(String.join(texts))))
}

// FILE: csvdata/tools/generate.nomi
// `nomi tool csvdata generate [--check]`: write tables.nomi from data/*.csv,
// a lookup function per file, and tables_test.nomi, a test that the files
// have not changed since. A file's header names the key and the value with
// their types, `code: String,basis_points: Int`; every other line is a key,
// a comma and a value. With `--check` it writes nothing and fails when a
// file is not what it would write.
import {
    std/fs
    std/io
    csvdata
}

struct App {
    args: List<String>
}

fn boot(startup: Startup) -> Result<App, String> {
    Ok(#App{args: startup.args})
}

fn main() -> Result<Unit, String> {
    check = case App.args {
        [] -> False
        ["--check"] -> True
        _ -> return Err("usage: nomi tool csvdata generate [--check]")
    }

    paths = fs.glob("data/*.csv") |> Result.map_err(fn e -> "data: ${e}")?
    tables = paths |> Iter.sort() |> Iter.map(table) |> Result.collect()?
    functions = String.join(tables, "\n\n")
    digest = csvdata.inputs_digest("data")?

    header = """
        // Generated by `nomi tool csvdata generate` from data/*.csv. Do not edit.
        // inputs sha256: ${digest}
        """

    tables_file = """
        ${header}
        ${functions}
        """

    test_file = """
        ${header}
        import csvdata

        test "generated tables are current" {
            assert csvdata.inputs_digest("data")
                == Ok("${digest}")
        }
        """

    changed = stale([#("tables.nomi", tables_file), #("tables_test.nomi", test_file)])
    names = changed |> Iter.map(fn #(path, _) -> path) |> String.join(", ")

    if Iter.is_empty(changed) {
        io.print("up to date")
    } else if check {
        return Err("${names} would change: run `nomi tool csvdata generate`")
    } else {
        write_all(changed)?
        io.print("wrote ${names}")
    }

    Ok(Unit)
}

// The files whose text on disk differs, each with the final newline a
// triple-quoted string leaves out.
fn stale(files: List<#(String, String)>) -> List<#(String, String)> {
    files
    |> Iter.map(fn #(path, text) -> #(path, text + "\n"))
    |> Iter.filter(fn #(path, text) -> fs.read_text(path) != Ok(text))
    |> Iter.to_list()
}

fn write_all(files: List<#(String, String)>) -> Result<Unit, String> {
    files
    |> Iter.map(fn #(path, text) -> {
        fs.write_text(path, text) |> Result.map_err(fn e -> "${path}: ${e}")
    })
    |> Result.collect()
    |> Result.map(fn _ -> Unit)
}

// The lookup function of the CSV file at path.
fn table(path: String) -> Result<String, String> {
    text = fs.read_text(path) |> Result.map_err(fn e -> "${path}: ${e}")?
    lines = String.lines(text) |> Iter.filter(fn l -> l != "") |> Iter.to_list()

    #(key, value, rows) = case lines {
        [first, ..rows] ->
            case String.split(first, ",") |> Iter.map(field) |> Iter.to_list() {
                [Some(k), Some(v)] -> #(k, v, rows)
                _ -> return Err("${path}:1: the header is `key: Type,value: Type`")
            }

        [] ->
            return Err("${path}: the file is empty; its first line is `key: Type,value: Type`")
    }

    #(key_name, key_type) = key
    #(value_name, value_type) = value

    name =
        String.split(path, "/")
        |> Iter.last()
        |> Maybe.with_default(path)
        |> String.replace(".csv", "")

    arms =
        rows
        |> Iter.with_index()
        |> Iter.map(fn #(i, row) -> {
            case String.split(row, ",") |> Iter.to_list() {
                [k, v] -> Ok("        ${cell(k, key_type)} -> Some(${cell(v, value_type)})")
                _ -> Err("${path}:${i + 2}: a row is a key, a comma and a value")
            }
        })
        |> Result.collect()?

    cases = String.join(arms, "\n")

    Ok(
        """
        /// The `${value_name}` of each `${key_name}` in ${path}.
        pub fn ${name}(${key_name}: ${key_type}) -> Maybe<${value_type}> {
            case ${key_name} {
        ${cases}
                _ -> None
            }
        }
        """
    )
}

// A header cell `name: Type`, as the name and the type.
fn field(cell: String) -> Maybe<#(String, String)> {
    case String.split(cell, ":") |> Iter.map(String.trim) |> Iter.to_list() {
        [name, type_name] when name != "" and type_name != "" -> Some(#(name, type_name))
        _ -> None
    }
}

// A cell as Nomi source: a string literal for a String, else the cell as it
// is, which the checker then checks against the type.
fn cell(text: String, type_name: String) -> String {
    if type_name == "String" {
        String.to_literal(text)
    } else {
        String.trim(text)
    }
}

// FILE: csvdata/nomi.toml
[module]
name = "csvdata"

// FILE: csvdata/go.mod
module csvdata

go 1.27.0
```

## Where to go next

sqlkit's `generate` is a whole generator built this way. It reads SQL
migrations and query files, asks SQLite to describe each query, and writes
the schema's row types and a typed function per query. Each file it writes
carries a SHA-256 of its inputs in the header, and it has `--check` and a
generated test. The next chapter,
[Databases](/databases/#checked-sql-with-sqlkit), walks through it.
